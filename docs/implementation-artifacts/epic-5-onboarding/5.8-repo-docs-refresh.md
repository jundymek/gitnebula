### Debug Log References

- **The demo recorder's own first take had the worktree on the map.** `plan.md`
  and an `.intent-acks/` module were nodes in frame, because the recorder was
  pointed at a live worktree. The recipe now clones into a temp directory; this
  is also why the README's transcript reports 399 nodes where the same command
  in a worktree reports more.
- **Three defects in three lines of the clone recipe, found by running it
  rather than reading it.** (1) `git clone --branch $(git rev-parse --abbrev-ref
  HEAD)` fails on a detached HEAD, which reports the literal string `HEAD`
  (Codex). (2) Cloning from `.` makes `repo.name` the worktree path, because the
  name is the last segment of the remote URL. (3) The clone's *local* branch
  name does not reach `repo.defaultBranch` — that is read from the remote's
  advertised HEAD, which a clone of a worktree inherits from the worktree — so
  every "open on github" link in the demo pointed at `story/5.8-…`, a branch
  that stops existing when this PR is squashed. All three are fixed and each was
  re-run, including the recipe executed verbatim from a genuinely detached
  checkout.
- **A real defect found while measuring, reported and not fixed:
  `packages/viz/src/engine/layout.ts` line 238 joins a map key with a literal
  NUL byte**, so the scanner classifies the file as binary and gitnebula's map
  of its own repository draws its force-layout engine at `loc: 0`. Reproduced
  on a clean clone at `4ffbee0`, NUL at byte 8879. `engine/` is not this story's
  territory and both wave-B peers were editing it, so it was reported rather
  than patched; it is now story **5.10** (PR #65). Story 5.7's owner had already
  copied the same idiom into `layout3d.ts` before the message reached him and
  changed it to a nested map.
- **I then made the same mistake myself, which is the evidence for the
  finding.** Codex's auto-review reported `scan: binary-file ×3 (e.g.
  DECISIONS.md)`: quoting the offending line had copied the raw byte into my own
  notes, invisibly, because every tool in the path renders it as a space.
  Gitignored, so nothing reached the repository; committed files verified at
  zero NUL bytes.
- **I reported that finding half-wrong and corrected it to three recipients.**
  I claimed the NUL costs the file its LOC *and* its imports. Measured, it keeps
  3 out-edges and 4 in-edges — `deps` does not read the scanner's `binary` flag.
  The distinction matters: "drawn as an empty node" is cosmetic, "loses its
  dependencies" would mean the map understates the engine's coupling. The
  measurement is now story 5.10's AC-5 expectation.
- **`grep` cannot find the byte.** Story 5.6's owner ran a PCRE grep for `\x00`
  across the tree while checking the finding and it reported nothing, including
  the file that provably contains one. Recorded in the story docs with a
  byte-count check that works, because 5.10's implementer will go looking.
