## Story

As a visitor deciding whether gitnebula is worth running,
I want the README to describe the tool as it now behaves,
So that the documentation does not promise the previous version's product.

## Context (binding)

- PRD FR-33; UX-DR16 (the README leads with the question the tool answers,
  not a feature list).
- **The README currently makes claims Epic 5 falsifies.** Two are named
  explicitly: the "everything outside the hovered node's one-hop chain dims
  to ~0.2 opacity" line, which story 5.2 replaces (out-of-chain elements now
  rest at 0.55 node / 0.12 edge and the chain is carried by emphasis), and
  the navigation description, which story 5.4 extends with drill-down. Find
  the rest by reading against the merged wave A and wave B work rather than
  by trusting this list to be exhaustive.
- **`CLAUDE.md`'s frozen-artifact rule applies.** `docs/planning-artifacts/`
  and `docs/implementation-artifacts/` are append-only once frozen: content
  describing completed work is never rewritten or deleted. Appending a new
  section is how those documents grow; a change that would *contradict*
  frozen content lands as a new versioned file naming what it supersedes.
  The README and `docs/recording-demo.md` are **not** frozen artifacts —
  they are the product's documentation and are revised in place.
- **A placeholder demo is forbidden at story close**, exactly as in story
  4.3. The recipe in `docs/recording-demo.md` must match what was actually
  used to record the demo that ships.
- Everything in the repository is in English (`CLAUDE.md` language protocol).

## Acceptance Criteria

- AC-1: Every README statement contradicted by Epic 5 is corrected —
  specifically the hover-dimming line replaced by story 5.2 and the
  navigation description extended by story 5.4 — and no claim is made that
  the shipped code does not support. Each corrected claim is traceable to the
  story that changed it, listed in the story's docs artifact (FR-33).
- AC-2: The README documents the capabilities this epic adds — start-here
  ranking (5.1), blast radius (5.6), layer filtering (5.3), drill-down and
  connected-only (5.4), the legible analysis window (5.5) and the 3D view
  (5.7) — and leads with the question the tool answers ("where do I start
  reading this repo") rather than a feature list (UX-DR16).
- AC-3: The demo reflects the onboarding-first flow rather than the
  pre-Epic-5 flow, and `docs/recording-demo.md` is updated to match the
  recipe actually used. A placeholder fails this AC.
- AC-4: No frozen artifact under `docs/planning-artifacts/` or
  `docs/implementation-artifacts/` is rewritten: documentation updates are
  appends, or land as a new versioned file naming what they supersede. The PR
  diff over those two directories contains no deletion or rewrite of content
  describing completed work.
- AC-5: The repository's own checks pass — `pnpm test` and `pnpm build` are
  green, and any command the README instructs a visitor to run has been run
  and works as written (the `npx gitnebula` path included).
- AC-6 (human-review): The maintainer reads the README as a stranger would
  and confirms it describes the product that now exists. Recorded as an
  unticked item in `MANUAL_TESTING.md`.
