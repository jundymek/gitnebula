## Story

As a developer dropped into an unfamiliar repository,
I want the map to tell me what to read first,
So that I get a reading order instead of an inventory.

## Context (binding)

- PRD FR-26, UX-DR12, UX-DR14; NFR-11 (no contract change), NFR-12
  (determinism), AD-5 (chrome ↔ engine only through the interface), AD-6
  (seeded, reproducible output).
- **Zero contract change.** `schemaVersion` stays `"1.0"`. The three
  categories are computed in the Viewer from `analysis.json` as it already
  stands — file-level `edges` give in-degree and out-degree, `nodes[].layer`
  gives the test classification. If this story appears to need a contract
  field, stop and report it rather than widening scope.
- **Why this story exists.** Measured on a real langgraph checkout (662
  nodes): the map opens as an inventory of everything and answers no
  question. The ranking was verified against that data — core is headed by
  `typing.py` at 259 in-edges, entry points number 32 with
  `bench/__main__.py` at the head, and tests-as-documentation is headed by
  `test_pregel.py` at 26 out-edges. A ranking that does not reproduce that
  shape on langgraph-like input is wrong.
- **Determinism (NFR-12, AD-6).** Ranking ties break on `id`. `localeCompare`
  is forbidden anywhere in this story — it is locale-dependent and would make
  the list a function of the reader's machine.
- The existing selection/flight path is story 3.3's `flyTo` plus the `select`
  engine event that story 3.4's panel consumes. Reuse it; do not add a second
  way to move the camera.

## Acceptance Criteria

- AC-1: Three categories are computed from the graph alone: **core** =
  `kind: file`, `layer != test`, ranked by in-degree descending;
  **entry points** = `kind: file`, `layer != test`, in-degree 0 and
  out-degree > 0, ranked by out-degree descending; **tests as documentation**
  = `layer == test`, ranked by out-degree descending. The three lists are
  disjoint by construction. Ties break on `id`; no `localeCompare` appears in
  the story's code — an automated test asserts the same document yields a
  byte-identical list across two computations (FR-26, NFR-12).
- AC-2: On the langgraph fixture (or an equivalent multi-package Python
  repo), core is headed by the most-imported non-test file, entry points
  contain no file with `layer == test`, and tests-as-documentation is
  non-empty — asserted by a test over a fixture, not by inspection.
- AC-3: On first load with no prior selection, the start-here panel is the
  default first state once the viewer finishes settling; it is dismissible,
  and reopening it from the header does not reload the document or re-run the
  settle (UX-DR12).
- AC-4: Selecting an entry flies the camera to that node and opens its detail
  panel by reusing the existing `flyTo` + `select` path — no new camera code
  in `chrome/`, and `chrome/boundary.test.ts` keeps passing unchanged (AD-5).
- AC-5: A category with no members states why it is empty ("no files with
  `layer: test` in this repository") instead of rendering a blank block, and
  a test mounts the panel against a fixture lacking a test layer and asserts
  the explanatory text is present (UX-DR14).
- AC-6 (human-review): On a real langgraph-scale repository, the three lists
  read as a plausible reading order to the maintainer. Recorded as an
  unticked item in `MANUAL_TESTING.md`.

### Completion Notes List

- All six acceptance criteria are covered; AC-6 is the human-review item and is
  recorded unticked in `MANUAL_TESTING.md` as the spec asks.
- **`core` is filtered to in-degree > 0.** AC-1 asks for core as "non-test
  files ranked by in-degree" *and* promises the three lists are disjoint by
  construction; unfiltered, core would contain every entry point at the bottom
  of its list. The disjointness clause is taken as binding. This is the one
  deliberate narrowing of the spec's literal wording and it is flagged in the
  PR body.
- **All three categories are file-level.** AC-1 names `kind: file` for two of
  the three and only `layer == test` for the third; modules carry a layer too,
  and a directory is not something to read.
- **Degrees count file→file import edges only** — `edges` carries both levels
  (ADR-0005), and a module edge's weight would inflate a file's degree with its
  directory's traffic. The fixture contains module edges so the test can see it.
- **No engine listener was added.** The first-load open is driven by the chrome
  store's `settling` field, because `connectEngine` is shared ground in this
  five-story wave and the fake engine in `chrome.test.ts` keeps one listener
  per event. `chrome/boundary.test.ts` passes unchanged (AD-5).
- **No global keyboard shortcut.** `Escape` is story 5.4's scope exit; the
  ownership was agreed in writing with that story's agent at intent-sync.
- **Five entries per category** (`START_HERE_LIMIT`); the model returns the
  complete ranking and the panel states how many are below the cut. The spec
  sets no limit, and a list of every file is the inventory this story replaces.
- Zero contract change: `schemaVersion` stays `"1.0"`, no fixture was added to
  `packages/contract/fixtures/`, and the langgraph-shaped document AC-2 is
  asserted against is a viz-local builder.
- Verified: `pnpm lint`, `pnpm test` (all six packages), `pnpm --filter
  @gitnebula/viz typecheck` and `pnpm build` all exit 0. Viz suite 383 → 422.
