## Story

As a developer reading a node's metrics,
I want to know that they describe a 90-day window,
So that a zero reads as "quiet lately" rather than "broken tool".

## Context (binding)

- PRD FR-31; UX-DR14 (empty states name their cause and offer the exit),
  UX-DR7 (panel layout), NFR-11 (no contract change), AD-1 (the Viewer does
  not compute new aggregations — it reads what the contract carries).
- **Why this story exists.** Measured on a real langgraph checkout: **386 of
  650 files carry `commits: 0`** because their last change predates the
  window, and the panel renders a bare `0`. The number is correct and the
  presentation is a bug report waiting to happen.
- **The window value is data, never a literal.** It is read from
  `repo.analysisWindowDays` in `analysis.json`. Hardcoding `90` anywhere in
  this story fails AC-1; the wording must work for any window value.
- A node with `lastChangedAt: null` has no commit inside the window. That is
  distinct from a node with history in the window, and both are distinct from
  a repository with no commits in the window at all.
- `--window-days` is the CLI lever that widens the window. Name it where a
  user meets an empty state (UX-DR14).
- The contract is unchanged: `schemaVersion` stays `"1.0"`.

## Acceptance Criteria

- AC-1: Every history metric in the panel states the window it covers,
  sourced from `repo.analysisWindowDays` and never hardcoded; a test renders
  the panel against a fixture whose window is **not** 90 and asserts the
  rendered copy carries that value (FR-31).
- AC-2: A node with `lastChangedAt: null` is presented as "no change in the
  last N days" and is visibly distinct in the rendered output from a node
  that has history in the window; the panel names `--window-days` as the way
  to widen it (UX-DR14).
- AC-3: A repository with no commits at all in the window states the
  zero-history case once, clearly, rather than repeating a bare zero on every
  node — asserted against a zero-history fixture.
- AC-4: In heatmap mode, when most nodes have zero churn, the mode's legend
  or empty state says so, so that a nearly-uniform heatmap is understood as
  data rather than as a rendering failure.
- AC-5: The `packages/cli` terminal summary wording states the analysis
  window it used. Wording only — no pipeline, config, or analyzer logic
  changes, and the cli test suite passes unchanged.
- AC-6: `chrome/boundary.test.ts` keeps passing unchanged, and no new
  aggregation is computed in the Viewer (AD-1, AD-5).

### Debug Log References

- **Two fixtures already carried a non-90 window, so no contract change was
  needed.** `single-module.json` and `zero-history.json` are both 365-day
  documents, which is exactly what AC-1's "not 90" test requires. The story
  therefore stays entirely out of `packages/contract/`.
- **A second `mode` subscription silently broke the mode toggle.** My intent
  promised the cohort an appended `off` entry rather than an edit to the
  existing handler. That failed three tests in `chrome.test.ts`: its engine
  double stores listeners in a `Map<event, listener>`, so the second
  subscription replaced the first. The real `Emitter` uses a `Set` and would
  have worked — relying on that difference would have been a trap, so the
  legend call is one line inside the existing handler instead. Peers informed.
- **New assertions were watched fail before being relied on.** Hardcoding the
  caption to 90, reverting the empty-state copy to the em dash and dropping the
  legend's mode check produced 6 failures across 3 files; restored, 455 pass.
- **The spec's cli test command is a false green.**
  `pnpm --filter @gitnebula/cli test` matches no project and **exits 0** — the
  package is named `gitnebula`. Ran `pnpm --filter gitnebula test` (145 passed).
  Likely affects other stories' specs.
- **Intent-sync markers were wiped mid-implementation.** `intent.ready`,
  `.intent-acks/` and `intent.synced` vanished from the worktree (coinciding
  with the `rebase_pending` marker for PR #52), re-closing the write gate. The
  markers were restored from the evidence in `events.log`, which records all
  four peer acks and `rambo intent-synced` at 15:08:42Z. Harness defect,
  reported rather than patched, per the supervised addendum.
- **The default window really is 90**, confirmed by running the built CLI; the
  committed fixtures are 365. That gap is why AC-1's test is meaningful.

### Completion Notes List

- All six ACs implemented and verified. AC-1 through AC-4 were additionally
  verified against **real pipeline output** — three bundles built from the
  repository's deterministic fixture at windows of 90, 400 and 1000 days —
  not only against committed fixtures.
- **AC-1 is met with a labelled group, not a per-label suffix.** The four
  history rows sit in a `role="group"` captioned `history · last {N} days`;
  the static `files`/`loc` rows stay outside. Suffixing would produce
  `last change 365d`. The group states the window for every metric inside it,
  visually and via `aria-label`. Recorded in `DECISIONS.md` §1 — if the
  supervisor wants the literal per-label form, `MetricRow.history` already
  marks exactly the right four rows.
- **AC-3 beats AC-2 by design.** In a zero-history repository every node is
  also out of window, so the repository-level notice suppresses the per-node
  one; otherwise the same sentence repeats on every node the reader opens,
  which is the failure AC-3 names. Asserted for every node of the fixture.
- **AC-4's count is not a new aggregation** (AD-1). It is a display-time count
  over contract-carried values, the same shape as the existing
  `modules: nodes.filter(kind === "module").length` in `mountChrome`.
  Threshold is a strict majority of file nodes at zero churn.
- **`chrome/format.ts` was deliberately not changed**, despite being in my
  territory. `formatRelativeTime` stays a pure function of `(iso, now)`; the
  empty-state branch needs the window and lives in `panel-model.ts`.
- **Empty-state conventions are established in `chrome/empty-state.ts`** for
  5.6, and all three peers who asked for them (5.1, 5.3, 5.4) deliberately
  copied the *shape* rather than importing the module — a cross-branch import
  would leave their branches uncompilable until this PR merges, for a
  dependency none of them declared. The duplication is intentional and
  consolidating it is 5.6's job; documented so it does not read as drift.
- **Not fixed, reported instead: the legend has no key for the `other`
  layer** (found by pamela, whose filter exposes all five). `LAYER_COLOR`
  deliberately gives `other` the same grey as `infra`, so a fifth entry would
  render two identical swatches — it needs a palette decision (UX-DR1), not a
  line of code, and this story is about the analysis window. `DECISIONS.md` §6.
- Nothing in this story keys off `ChromeState.settling`, so alice's
  reduced-motion finding does not affect it.
