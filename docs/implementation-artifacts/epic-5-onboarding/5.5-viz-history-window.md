## Story

As a developer reading a node's metrics,
I want to know that they describe a 90-day window,
So that a zero reads as "quiet lately" rather than "broken tool".

## Context (binding)

- PRD FR-31; UX-DR14 (empty states name their cause and offer the exit),
  UX-DR7 (panel layout), NFR-11 (no contract change), AD-1 (the Viewer does
  not compute new aggregations — it reads what the contract carries).
- **Why this story exists.** Measured on a real langgraph checkout: **386 of
  650 files carry `commits: 0`** because their last change predates the
  window, and the panel renders a bare `0`. The number is correct and the
  presentation is a bug report waiting to happen.
- **The window value is data, never a literal.** It is read from
  `repo.analysisWindowDays` in `analysis.json`. Hardcoding `90` anywhere in
  this story fails AC-1; the wording must work for any window value.
- A node with `lastChangedAt: null` has no commit inside the window. That is
  distinct from a node with history in the window, and both are distinct from
  a repository with no commits in the window at all.
- `--window-days` is the CLI lever that widens the window. Name it where a
  user meets an empty state (UX-DR14).
- The contract is unchanged: `schemaVersion` stays `"1.0"`.

## Acceptance Criteria

- AC-1: Every history metric in the panel states the window it covers,
  sourced from `repo.analysisWindowDays` and never hardcoded; a test renders
  the panel against a fixture whose window is **not** 90 and asserts the
  rendered copy carries that value (FR-31).
- AC-2: A node with `lastChangedAt: null` is presented as "no change in the
  last N days" and is visibly distinct in the rendered output from a node
  that has history in the window; the panel names `--window-days` as the way
  to widen it (UX-DR14).
- AC-3: A repository with no commits at all in the window states the
  zero-history case once, clearly, rather than repeating a bare zero on every
  node — asserted against a zero-history fixture.
- AC-4: In heatmap mode, when most nodes have zero churn, the mode's legend
  or empty state says so, so that a nearly-uniform heatmap is understood as
  data rather than as a rendering failure.
- AC-5: The `packages/cli` terminal summary wording states the analysis
  window it used. Wording only — no pipeline, config, or analyzer logic
  changes, and the cli test suite passes unchanged.
- AC-6: `chrome/boundary.test.ts` keeps passing unchanged, and no new
  aggregation is computed in the Viewer (AD-1, AD-5).
