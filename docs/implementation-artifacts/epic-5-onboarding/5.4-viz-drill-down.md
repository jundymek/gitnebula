## Story

As a developer facing 650 nodes at once,
I want to scope the map to one module and hide the nodes that carry no edges,
So that I can look at a part of the repository instead of all of it.

## Context (binding)

- PRD FR-30; UX-DR14 (empty and hidden states name their cause), NFR-11 (no
  contract change), AD-5, AD-6.
- **Why this story exists.** Measured on a real langgraph checkout: the
  unscoped view puts 650 nodes on one screen, **232 of them carry no edge at
  all**, and pointer hit-areas cover 78% of the viewport at 6× zoom. Scoping
  is the only lever that reduces what is drawn rather than restyling it.
- **Scoping is a frame concern, not a layout concern.** The simulation keeps
  running on the whole graph; scoping filters the built scene. This is what
  makes leaving a scope instant and guarantees the settle is never re-run.
  Measured scene sizes: whole repository 662 nodes / 2388 edges;
  `libs/langgraph/` scope 169 / 917.
- **A working prototype exists**: `git stash show -p stash@{0}` — module
  focus in `engine.ts`, scoping applied to the finished scene in the
  scene-building path, a `dblclick` gesture, and a `keydown` listener on
  `globalThis` (a canvas is not focusable, so a canvas-level keydown never
  fires — that detail is worth keeping). It is experimental and uncommitted:
  read it as prior art and as a source of measurements, adopt what the ACs
  need, and do not treat it as a base to apply. Its `stash@{1}` sibling (the
  label budget) belongs to story 5.2's territory.
- **Decision taken by the maintainer, binding on this story.** When search
  targets a node outside the active scope, **the scope is left and the
  camera flies to the target**; the chrome states that the scope was left and
  offers a way back. Search stays globally useful; the scope is a view
  filter, not a cage. A silent no-op is not acceptable.
- The single click already means "select" (story 3.4). The drill-down gesture
  must be a distinct one.
- Determinism (AD-6): scoping never introduces unseeded randomness, and the
  set of nodes a given scope carries is a pure function of the document.

## Acceptance Criteria

- AC-1: A dedicated gesture (not the single click, which means "select")
  scopes the map to a module: that module, its member files, and the modules
  it actually imports or is imported by; everything else leaves the frame
  (FR-30).
- AC-2: The scope is exited by an equally discoverable gesture **and** by
  `Escape`, and the current scope is always visible in the chrome — a test
  asserts the scope indicator is present whenever a scope is active, so a
  user can never be unable to tell they are scoped or how to leave.
- AC-3: With the connected-only filter enabled, nodes of degree 0 are not
  drawn, and the count of what was hidden is stated in the chrome rather than
  silently dropped (measured baseline: 232 of 650 files on langgraph)
  (UX-DR14).
- AC-4: Scoping affects what the frame carries, not what the simulation
  computes: entering and leaving a scope does not re-run the settle, and an
  automated test asserts node positions are unchanged across a
  scope/unscope cycle.
- AC-5: When search targets a node outside the active scope, the scope is
  left and the camera flies to the target through the existing `flyTo` path;
  the chrome states that the scope was left and offers a one-click return.
  Asserted by a test — a silent no-op fails this AC.
- AC-6: Nodes excluded by scope or by connected-only cannot be hovered or
  picked (they are absent from the frame, not dimmed), and
  `chrome/boundary.test.ts` keeps passing unchanged (AD-5).
- AC-7 (human-review): On a real langgraph-scale repository, drilling into a
  module and leaving it feels immediate and the scope is obvious at a glance.
  Recorded as an unticked item in `MANUAL_TESTING.md`.

### Debug Log References

- **The langgraph-shaped fixture cannot test connected-only.** Story 5.1's
  `test-support/langgraph-shape.ts` was built so every file ranks, which means
  every file has an edge — zero degree-0 nodes. The AC-3 assertions moved to
  `synthetic-100x2000` (869 edgeless files of 2,000), which is the same shape
  of problem at the FR-12 fixture scale. The langgraph fixture still pins what
  a scope *contains*.
- **Connected-only is invisible at rest on a large fixture.** At default zoom
  the frame carries top-level nodes only, and every module in the synthetic
  fixture has members, so nothing is edgeless up there. The frame-level
  assertion had to unfold a module first (ADR-0006); the document-level count
  is asserted separately. First version of the test failed on this and was
  wrong, not the code.
- **A neighbour module is not "outside the scope".** The first version of the
  AC-5 wiring test flew to "any other module" and asserted the scope was left;
  it failed because a neighbour module is *in* scope by AC-1. The helper now
  picks a genuine non-member via `inScopeIds`. Test bug, not a code bug.
- **`grep` reports 0 matches in the built viewer.** `packages/viz/dist/index.html`
  trips grep's binary heuristic — the CLI's own scanner classifies it the same
  way (`scan: binary-file`). Without `grep -a` every string search returns 0
  and the feature looks absent from the shipped bundle when it is present
  (19 × `scope-bar`). Recorded because it looks exactly like a build failure.
- **Three real defects found by the Codex review, all fixed, each pinned by a
  test watched red first.**
  1. *Scoping revealed no files.* The scope filter only permitted member files;
     they are produced by the viewport unfold rule, so at overview zoom a
     drill-down showed the module and its neighbours and none of its files —
     the one thing the gesture exists to reveal. `setScope` now pins the focus
     module unfolded and releases it on the way out.
  2. *Connected-only disagreed with what was drawn.* Degree was counted over
     the whole graph, so a scoped node whose only import left the scope
     counted as connected while `buildScene` dropped that edge. A probe over
     `synthetic-100x2000` found **1,131** such nodes. `degreeOf` now takes a
     candidate set and the filter runs to a fixpoint.
  3. *Stale interaction state.* Hover, selection and isolate survived the node
     they pointed at leaving the frame, so the panel kept describing an
     off-map node. Now reconciled after either filter changes, exactly as
     story 5.3's layer filter already did.
- **A second review pass found two more, and they were one design mistake.**
  Chrome was inferring whether to offer a way back out of a scope rather than
  being told: leaving with `Escape` announced "left the scope to reach your
  search result" when no search had happened, and loading a new document left
  the offer pointing into the previous repository, where clicking it no-opped
  forever. The `scope` event now carries `returnToScopeId` — the state of the
  offer, not a breadcrumb of the last scope visited — and chrome mirrors it.
- **A regression test can pass for the wrong reason.** The first version of the
  connected-only-within-scope test used the langgraph-shaped fixture and went
  green *with the bug still in place* — that fixture simply has no node in the
  failing shape (a probe confirmed 0 occurrences there and on this repository's
  own 401-node document, against 1,131 on the synthetic fixture). Reverting the
  fix and watching the test stay green is what caught it; the test was moved to
  the fixture where the case actually exists.
- **`Escape` on the canvas never fires.** A canvas is not focusable. The
  listener is on `globalThis`, which is the one detail worth keeping from the
  uncommitted `stash@{0}` prototype the spec points at.
- **`git push --force-with-lease` was skipped during the epic rebase.** The
  `epic-updated` recipe ends in that command, but this branch had no commits of
  its own and its upstream was `origin/epic/5-onboarding` — running it verbatim
  would have pushed the epic branch, which agents may never do. The rebase was
  a clean fast-forward onto `9c28344`; nothing of mine needed publishing.

### Completion Notes List

- **All seven ACs implemented; AC-7 is human-review and is left unticked in
  `MANUAL_TESTING.md` for the owner**, as the spec asks.
- **Scoping is implemented as a frame filter, never a layout one.** Nothing in
  this story calls `startSettle`, `runToSettled` or `new ModuleLayout`, and
  nothing draws from the RNG (AD-6). AC-4 is therefore true by construction,
  and asserted anyway: positions identical across a scope/unscope cycle and no
  `settle-start` emitted.
- **One predicate gates both the scene and the pick loop**, which is what makes
  an excluded node genuinely absent rather than invisible-but-clickable (AC-6).
  `chrome/boundary.test.ts` passes byte-unchanged.
- **Two judgement calls, both recorded in `DECISIONS.md`:** a neighbour module
  is in scope but its member files are not (AC-1 read literally); and a
  module's degree counts its member files, so connected-only cannot delete a
  module with twenty files and no imports and take its subtree with it.
- **Deliberate deviation — no `engine/index.ts` export was added.** The intent
  listed one, but chrome needs nothing new from the barrel: the scope bar
  reaches the map through the `GraphEngine` interface that was already
  exported. Adding an export nothing imports would have been dead surface.
- **Known gap, not fixed, flagged rather than hidden:** if `connected-only`
  alone hides a search target, the camera still flies to a node that is not
  drawn. AC-5 covers the scope case only; extending the same principle would
  widen this story into a file three agents are editing this wave.
- **Declined, with reason:** story 5.1's owner suggested an `isSettled()`
  accessor on `GraphEngine` while I was appending members anyway. Nothing here
  keys off `settling`, no AC asks for it, and it belongs to one owner in one
  branch rather than to whoever happens to be editing the interface.
- **Cohort coordination.** Every `engine.ts` hunk was announced before it was
  written. Agreed order in `buildScene`: 5.3's narrowing, then this story's,
  then 5.2's `focusId`/`chain` pair. 5.2 lands first and this branch rebases
  onto it. The hidden-count question was settled with 5.3's owner in writing:
  each filter names its own cause and neither prints a combined total, because
  the two overlap and are not additive.
- **Verification.** `pnpm lint`, `pnpm test` (workspace), `pnpm --filter
  @gitnebula/viz typecheck` and `pnpm build` all exit 0. viz: 493 tests. The
  feature was also confirmed in a real served viewer over a 401-node document
  generated from this repository.
