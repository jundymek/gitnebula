## Story

As a developer interested in one side of a mixed repository,
I want to filter the map by layer,
So that I can look at the backend without the frontend and tests on top of it.

## Context (binding)

- PRD FR-28; UX-DR13 (filter controls carry `aria-pressed`, active set
  visible without opening a menu), UX-DR6 (styling matches the existing mode
  toggle), UX-DR14 (empty states name their cause), FR-22 (PNG export matches
  what is on screen), NFR-11 (no contract change), AD-5.
- The five contract layers are `backend`, `frontend`, `infra`, `test`,
  `other` — read from `nodes[].layer`, which already exists.
  `schemaVersion` stays `"1.0"`.
- **Excluded means not drawn, never dimmed.** This is the point of the story
  and the difference from story 5.2's work: measured on langgraph, pointer
  hit-areas cover 78% of the viewport at 6× zoom, so a node that is merely
  dimmed still catches the pointer. A filtered-out node must leave the frame
  entirely, so it cannot be hovered, picked, or counted as hit-area.
- `chrome/mode-toggle.ts` is the styling and `aria-pressed` precedent to
  follow (UX-DR6/UX-DR13). The mode toggle is single-select; this control is
  multi-select.
- Filtering changes what the frame carries, not what the simulation computes
  — the layout keeps running on the whole graph, so toggling a layer back on
  must not re-run the settle.

## Acceptance Criteria

- AC-1: Each of the five layers is independently toggleable (multi-select),
  every control carries `aria-pressed` reflecting its state, and the active
  set is visible without opening a menu; styling matches the existing mode
  toggle (FR-28, UX-DR13, UX-DR6).
- AC-2: With one or more layers excluded, excluded nodes are **not drawn at
  all** — not dimmed — and therefore cannot be hovered or picked; a test
  asserts both that they are absent from the rendered scene and that a
  pointer over their position produces no hover.
- AC-3: An edge is drawn only when both of its endpoints survive the filter;
  asserted by a test over a fixture with a cross-layer edge.
- AC-4: A filter excluding every layer renders a named empty state ("no nodes
  match the active filters") with a one-click way back to the unfiltered map
  (UX-DR14).
- AC-5: With an active filter, PNG export matches what is on screen, filters
  included — FR-22's "matches camera/mode/highlight" extends to filters;
  asserted by a test over the export path.
- AC-6: Toggling a layer off and back on does not re-run the settle — the
  simulation keeps running on the whole graph, and an automated test asserts
  node positions are unchanged across the toggle.
- AC-7: `chrome/boundary.test.ts` keeps passing unchanged (AD-5).

### Debug Log References

- **Export scale.** The first AC-5 test called `exportPNG({ scale: 1 })` and
  failed against `export.ts`'s AD-5 guard (`scale must be >= 2`). The default
  scale is correct for the comparison — the scaling happens through
  `setTransform`, which story 3.5's signature helper already filters out — so
  the option was dropped rather than the guard questioned.
- **Counts in the `filter` event.** The first wiring computed the surviving
  node count in chrome as `engine.nodes.length - hidden`. That is wrong against
  a stubbed engine and fragile against a real one, since `nodes` is
  deliberately the *unfiltered* set. The event now carries `visible` alongside
  `hidden`, and chrome does no arithmetic.
- **Tests seen red.** Removing the `buildScene` narrowing and the `pick` guard
  fails four assertions (scene contents, pick-at-position, cross-layer edge,
  export label). Restored immediately; recorded because a test never seen red
  proves nothing.
- **Pre-existing defect inherited, not fixed.** Under `prefers-reduced-motion`
  the engine emits `settled` synchronously inside `load()`, before `app.ts`
  connects chrome. Story 5.1's merged workaround seeds `settling` from the
  media query. Nothing in this story keys off `settling`, so it is unaffected;
  the proper fix (a settle-state accessor on `GraphEngine`) reaches outside
  this story's territory and is left alone.

### Completion Notes List

- **Every AC met and asserted.** AC-1 (five multi-select toggles,
  `aria-pressed`, active set visible without a menu), AC-2 (absent from the
  scene *and* unpickable at its former position), AC-3 (both endpoints), AC-4
  (named empty state with a one-click reset), AC-5 (export re-renders the
  filtered scene), AC-6 (identical positions across a toggle, no
  `settle-start`), AC-7 (`chrome/boundary.test.ts` byte-unchanged).
- **The filter is an engine concern reached through appended interface
  members** — `getLayerFilter` / `setLayerFilter` plus a `filter` event — as
  the spec's territory note allows. AC-2's unpickability cannot be delivered
  from chrome, which AD-5 keeps away from the canvas entirely. Every hunk was
  announced in `intent.md` and confirmed in writing by the owners of the two
  contended files (5.2's and 5.4's agents) before it was written.
- **AC-5 needed no export code.** `exportPNG` already delegates to
  `buildScene`, so filtering the scene filters the export by construction; the
  work was the test proving the two paths issue identical draw calls.
- **`engine.nodes` deliberately still returns every node.** The filter narrows
  the frame, not the node set — the search corpus and story 5.1's ranking read
  that getter.
- **Deviation from a literal reading of AC-4:** the empty state triggers when
  *nothing survives*, which includes but is wider than "a filter excluding
  every layer". A repository that is all one layer with that layer off is the
  same dead map. Reasoned in `DECISIONS.md` D4.
- **Judgement call not named by any AC:** a selection whose node is filtered
  out is cleared along with its isolate state (`DECISIONS.md` D3). The
  alternative leaves story 3.4's panel describing an invisible node.
- **Two hidden counts, by agreement with story 5.4's owner:** each filter
  states its own cause (`N nodes hidden: layer filter`), and neither prints a
  combined total, because UX-DR14 asks for the cause and a merged total names
  none. The counts overlap and are deliberately not additive.
- **Empty-state wording is story 5.5's shape in this story's own file.** Its
  `chrome/empty-state.ts` does not exist on `epic/5-onboarding` until that PR
  merges and both stories are `depends_on: []`, so importing it would leave
  this branch uncompilable on an order neither owner controls. Consolidation is
  a wave-B follow-up (story 5.6).
- **Reported, not fixed:** `chrome/legend.ts` names four layers and omits
  `other`, which is the **largest** layer on this repository (145 of 363
  nodes). The filter exposes all five, so a reader gets an `other` toggle with
  no legend key. The legend is story 5.5's territory.
- **No contract change.** `schemaVersion` stays `"1.0"` (NFR-11).
- Verified: `pnpm --filter @gitnebula/viz test` (469 passing),
  `typecheck`, `pnpm lint`, `pnpm --filter @gitnebula/viz build`, and the
  shipped bundle checked over HTTP for this story's markup and copy.
