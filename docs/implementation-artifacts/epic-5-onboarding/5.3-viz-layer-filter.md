## Story

As a developer interested in one side of a mixed repository,
I want to filter the map by layer,
So that I can look at the backend without the frontend and tests on top of it.

## Context (binding)

- PRD FR-28; UX-DR13 (filter controls carry `aria-pressed`, active set
  visible without opening a menu), UX-DR6 (styling matches the existing mode
  toggle), UX-DR14 (empty states name their cause), FR-22 (PNG export matches
  what is on screen), NFR-11 (no contract change), AD-5.
- The five contract layers are `backend`, `frontend`, `infra`, `test`,
  `other` — read from `nodes[].layer`, which already exists.
  `schemaVersion` stays `"1.0"`.
- **Excluded means not drawn, never dimmed.** This is the point of the story
  and the difference from story 5.2's work: measured on langgraph, pointer
  hit-areas cover 78% of the viewport at 6× zoom, so a node that is merely
  dimmed still catches the pointer. A filtered-out node must leave the frame
  entirely, so it cannot be hovered, picked, or counted as hit-area.
- `chrome/mode-toggle.ts` is the styling and `aria-pressed` precedent to
  follow (UX-DR6/UX-DR13). The mode toggle is single-select; this control is
  multi-select.
- Filtering changes what the frame carries, not what the simulation computes
  — the layout keeps running on the whole graph, so toggling a layer back on
  must not re-run the settle.

## Acceptance Criteria

- AC-1: Each of the five layers is independently toggleable (multi-select),
  every control carries `aria-pressed` reflecting its state, and the active
  set is visible without opening a menu; styling matches the existing mode
  toggle (FR-28, UX-DR13, UX-DR6).
- AC-2: With one or more layers excluded, excluded nodes are **not drawn at
  all** — not dimmed — and therefore cannot be hovered or picked; a test
  asserts both that they are absent from the rendered scene and that a
  pointer over their position produces no hover.
- AC-3: An edge is drawn only when both of its endpoints survive the filter;
  asserted by a test over a fixture with a cross-layer edge.
- AC-4: A filter excluding every layer renders a named empty state ("no nodes
  match the active filters") with a one-click way back to the unfiltered map
  (UX-DR14).
- AC-5: With an active filter, PNG export matches what is on screen, filters
  included — FR-22's "matches camera/mode/highlight" extends to filters;
  asserted by a test over the export path.
- AC-6: Toggling a layer off and back on does not re-run the settle — the
  simulation keeps running on the whole graph, and an automated test asserts
  node positions are unchanged across the toggle.
- AC-7: `chrome/boundary.test.ts` keeps passing unchanged (AD-5).
