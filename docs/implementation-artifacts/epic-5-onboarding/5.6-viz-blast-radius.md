## Story

As a developer about to change a file,
I want to see what has historically changed together with it,
So that I learn what else I am likely to touch — knowledge no static analysis
can give me.

## Context (binding)

- PRD FR-27; UX-DR14 (empty states name their cause), UX-DR7 (panel layout),
  NFR-11 (no contract change), NFR-12 (determinism), AD-1 (no new
  aggregation in the Viewer), AD-5.
- **Why this story exists.** The `cochanges` array is already in the
  contract and **entirely unused by the UI**. Measured on a real langgraph
  checkout: **128 pairs exist, but only 52 of 662 nodes appear in any pair**
  — so the empty case is the majority case and must not read as a bug.
- **Read, never recompute.** Co-change pairs come from the contract as
  produced by `githist`. Computing new aggregations in the Viewer violates
  AD-1. `schemaVersion` stays `"1.0"`.
- **Ordering is deterministic**: by shared-commit count descending, then by
  `id`. No `localeCompare` (NFR-12).
- **Base-state facts from wave A.** Story 5.5 has already landed the
  empty-state copy conventions and the `repo.analysisWindowDays` labelling in
  your base. Reuse them — do not invent a second convention for the same
  problem. Story 3.4 already renders a top-3 co-changing modules row in the
  panel; this story is where co-change becomes a first-class section, so
  reconcile with that row rather than duplicating it.
- Co-change is **not** a dependency edge. Drawing it like one would tell the
  reader something false.

## Acceptance Criteria

- AC-1: A selected node's panel lists its co-change partners with their
  shared-commit counts, ordered by count descending then by `id`; asserted by
  a determinism test over a fixture, and no `localeCompare` appears in the
  story's code (FR-27, NFR-12).
- AC-2: Selecting a partner navigates to it through the existing selection
  path (`flyTo` + `select`) — no new camera or selection mechanism (AD-5),
  and `chrome/boundary.test.ts` keeps passing unchanged.
- AC-3: A node with no co-change partners gets a stated reason — below the
  ≥ 3 shared-commit threshold, or no shared commits inside the window — and
  names `--window-days` as the lever, following the empty-state conventions
  story 5.5 already put in the base. This is the majority case (measured: 610
  of 662 nodes appear in no pair) and must not read as a bug (UX-DR14).
- AC-4: When the map is asked to show a node's partners, the partner set is
  visually distinguishable from the import chain — a distinct encoding, not
  a dependency edge; asserted by an encoding test over the render state.
- AC-5: Module-level and file-level pairs are unambiguous to the reader, and
  a file's panel never shows a module pair as if it were the file's own —
  asserted by a test over a fixture carrying both levels.
- AC-6 (human-review): On a real repository, the blast-radius section tells
  the maintainer something the import graph did not. Recorded as an unticked
  item in `MANUAL_TESTING.md`.

### Debug Log References

- **`localeCompare` scan caught its own documentation.** The AC-1 source scan
  first failed on `panel-model.ts` because the banned method was named in the
  comment explaining why it is banned. The comment was reworded rather than the
  test weakened — a scan with an exception for comments is a scan somebody will
  eventually route around.
- **Story 5.5's "state it once" test failed for the right reason.** Giving the
  section's empty state the shared `.p-notice` class made 5.5's AC-3 assertion
  count two notices per panel. Fixed on two axes: the section carries its own
  class, and where the *repository* is quiet it renders nothing at all and lets
  the panel-level notice speak. That precedence rule was 5.5's; it is kept
  rather than reinvented.
- **Both central assertions were watched red before being relied on.** Deleting
  the `setLineDash` call turned the two dash tests red; making `buildScene`
  push edges between marked partners turned *"adds no edge to the scene"* red.
  Both mutations reverted.
- **Review found the bug my missing visual check would have hidden.** The
  partner list had no height bound, `#panel` had none either, and `body` is
  `overflow: hidden` — so the file this story's own docs cite as the example,
  with **44 partners**, pushed `show on map` and the panel's actions below the
  fold where they could not be reached. Before this story the panel's height
  was a fixed row count, so the unboundedness was introduced here. Both the
  list and the panel now carry the cap story 5.1's start-here panel already
  used, plus a test over the stylesheet that was watched failing with the cap
  removed. It is exactly the class of defect an unrun visual step leaves
  behind, which is the argument for leaving that box honestly unticked.
- **Codex review found a green suite hiding a red compiler.** A node fixture in
  `blast-radius.test.ts` omitted the contract's required `descriptionSource`.
  `vitest` does not type-check, so `pnpm lint`, `pnpm test` and `pnpm build`
  were all green while `tsc --noEmit` failed with TS2741. Fixed, and
  `pnpm -r typecheck` is now part of this story's recorded baseline — the
  lesson generalises past this branch.
- **Defect found by arnold (5.8) and reproduced here, deliberately not fixed.**
  `packages/viz/src/engine/layout.ts` contains a literal NUL byte at offset
  8879 (a raw `\0` inside a template literal on line 238), so the scanner's
  binary heuristic classifies the file as binary and gitnebula's map of its own
  repository carries `layout.ts` with `loc: 0` and no imports parsed. Confirmed
  independently on this branch from a fresh CLI run:
  `packages/viz/src/engine/layout.ts loc= 0`. It is one instance, not a
  pattern — `githist/src/cochange.ts` uses the two-character escape `"\0"` in
  source and scans correctly at `loc: 53`. Left unfixed on purpose: it is
  outside this story, and two agents were in `engine/` this wave. Reported to
  the cohort and recorded here so it is not lost.

  leaves a hole. No new event key.
