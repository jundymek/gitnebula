## Story

As a developer about to change a file,
I want to see what has historically changed together with it,
So that I learn what else I am likely to touch — knowledge no static analysis
can give me.

## Context (binding)

- PRD FR-27; UX-DR14 (empty states name their cause), UX-DR7 (panel layout),
  NFR-11 (no contract change), NFR-12 (determinism), AD-1 (no new
  aggregation in the Viewer), AD-5.
- **Why this story exists.** The `cochanges` array is already in the
  contract and **entirely unused by the UI**. Measured on a real langgraph
  checkout: **128 pairs exist, but only 52 of 662 nodes appear in any pair**
  — so the empty case is the majority case and must not read as a bug.
- **Read, never recompute.** Co-change pairs come from the contract as
  produced by `githist`. Computing new aggregations in the Viewer violates
  AD-1. `schemaVersion` stays `"1.0"`.
- **Ordering is deterministic**: by shared-commit count descending, then by
  `id`. No `localeCompare` (NFR-12).
- **Base-state facts from wave A.** Story 5.5 has already landed the
  empty-state copy conventions and the `repo.analysisWindowDays` labelling in
  your base. Reuse them — do not invent a second convention for the same
  problem. Story 3.4 already renders a top-3 co-changing modules row in the
  panel; this story is where co-change becomes a first-class section, so
  reconcile with that row rather than duplicating it.
- Co-change is **not** a dependency edge. Drawing it like one would tell the
  reader something false.

## Acceptance Criteria

- AC-1: A selected node's panel lists its co-change partners with their
  shared-commit counts, ordered by count descending then by `id`; asserted by
  a determinism test over a fixture, and no `localeCompare` appears in the
  story's code (FR-27, NFR-12).
- AC-2: Selecting a partner navigates to it through the existing selection
  path (`flyTo` + `select`) — no new camera or selection mechanism (AD-5),
  and `chrome/boundary.test.ts` keeps passing unchanged.
- AC-3: A node with no co-change partners gets a stated reason — below the
  ≥ 3 shared-commit threshold, or no shared commits inside the window — and
  names `--window-days` as the lever, following the empty-state conventions
  story 5.5 already put in the base. This is the majority case (measured: 610
  of 662 nodes appear in no pair) and must not read as a bug (UX-DR14).
- AC-4: When the map is asked to show a node's partners, the partner set is
  visually distinguishable from the import chain — a distinct encoding, not
  a dependency edge; asserted by an encoding test over the render state.
- AC-5: Module-level and file-level pairs are unambiguous to the reader, and
  a file's panel never shows a module pair as if it were the file's own —
  asserted by a test over a fixture carrying both levels.
- AC-6 (human-review): On a real repository, the blast-radius section tells
  the maintainer something the import graph did not. Recorded as an unticked
  item in `MANUAL_TESTING.md`.
