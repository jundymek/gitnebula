## Story

As someone reading a map of an unfamiliar repository,
I want one generated data file not to outweigh all of its source,
So that the map's sizes and layers describe the architecture rather than the
largest blob somebody committed.

## Context (binding)

- Radius is `∝ √LOC` (`packages/viz/src/engine/graph.ts`, UX-DR4).
- The default excludes already drop machine-written files on exactly this
  reasoning — lockfiles are "machine-written, enormous, and say nothing about
  architecture", and test snapshots were excluded because on excalidraw they
  "would decide its module layers on their own".
- Story 4.7 is the counter-pressure: what is wrongly kept off the map costs the
  reader real information.
- Zero-config (brief principle 1) rules out fixing this with a repository-local
  `.gitnebula.yml` entry: the default run must produce a useful map.
- Determinism (AD-4) is untouched by either candidate and must stay that way.

### Completion Notes List

- **Chosen mechanism: the scanner leaves generated data blobs out of the
  universe.** A data-language file (`json`, `yaml`, `toml`, `ini`, `xml`)
  longer than `DATA_BLOB_LOC_THRESHOLD` (5,000 lines) is dropped and counted as
  a `data-blob` warning naming the path.
- **The radius mechanism was rejected on measurement**, not on taste. It
  addresses the file disc only; the module disc is 3.41× the median radius, so
  any cap loose enough not to flatten genuine size differences leaves it
  untouched, and no view-side rule can fix the module being labelled `test`.
- **Dropped rather than kept at 0 LOC.** A binary file is kept at 0 because its
  line count is meaningless; a data blob's line count is true, and therefore
  misleading rather than absent. Dropping matches how excluded paths already
  leave the universe, before anything downstream sees them.
- **Threshold justified by the gap, not by taste**: largest hand-maintained
  data file here 229 lines, largest source file 1,694, the blob 40,655.
- **Known limit:** `.csv` and `.tsv` have no entry in the language table, so
  they detect as `unknown` and are out of reach of this rule. Adding them would
  change `stats.languages` for every repository — wider than this defect asks
  for, and recorded rather than done.
- AC-7 holds without any change: the fixture is loaded by `viz` from disk as a
  document, which the scanner's view of a *target repository* never touched.
