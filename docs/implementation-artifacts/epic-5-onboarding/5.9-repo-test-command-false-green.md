**Why a new story and not a correction to a live agent.** No story in the
epic-5 cohort owns spec hygiene or the workspace's test entry points, and the
defect predates the epic by two epics. It is nobody's to fix inside their own
scope.

## Story

As an agent or a maintainer verifying a change,
I want a test command that fails when it runs nothing,
So that "the suite is green" cannot mean "no suite was executed".

## Context (binding)

- The cli package is named `gitnebula`. The other five are scoped
  (`@gitnebula/contract`, `scanner`, `deps`, `githist`, `viz`). The correct
  invocation today is `pnpm --filter gitnebula test` — 145 tests.
- **`CLAUDE.md`'s frozen-artifact rule applies to the six spec files above.**
  `docs/planning-artifacts/` and `docs/implementation-artifacts/` are
  append-only once frozen: content describing completed work is never
  rewritten. Correcting a merged story's spec in place is therefore **out of
  scope** — the record of what that story was told to run is part of the
  history. Corrections land as an append or as a new versioned file naming
  what it supersedes.
- `CLAUDE.md` is product documentation, not a frozen artifact, and is revised
  in place.
- The repository's determinism and package-boundary rules are untouched by
  this story: it adds no source code to any package.

## Acceptance Criteria

- AC-1: A workspace filter that matches no project **fails** rather than
  exiting 0. Whichever mechanism is chosen (an `.npmrc` setting, a wrapper
  script, a root script that asserts the project list), an automated check
  demonstrates it: running the workspace test entry point with a
  deliberately-wrong filter exits non-zero and says which filter matched
  nothing.
- AC-2: The canonical per-package test command for each of the six packages is
  written down in one place in `CLAUDE.md`, with the cli's unscoped name
  called out explicitly as the exception that produced this defect, so a
  reader does not have to infer it from `package.json`.
- AC-3: An audit of the merged stories that carried the false command is
  recorded — for each of the six spec files, whether that story's PR body
  quoted a cli test result and, if so, whether the quoted output is consistent
  with a suite that actually ran. The audit states its own limits where a PR
  body is ambiguous. It is a finding record, not a re-verification of merged
  code.
- AC-4: No frozen artifact is rewritten. The PR diff over
  `docs/planning-artifacts/` and `docs/implementation-artifacts/` contains no
  deletion or rewrite of content describing completed work; corrections are
  appends or a new versioned file.
- AC-5: `pnpm lint` and `pnpm test` are green, and the real cli suite is run
  and its summary line quoted in the PR body (`pnpm --filter gitnebula test`,
  145 tests at the time of writing).
- AC-6: A story spec written after this one that names a package test command
  can be checked against AC-2's list mechanically — i.e. the list is a
  literal table of `<package name>` → `<command>`, not prose.

## Correction — 2026-08-15, supervisor, after Codex review

**The provenance section above overstates the history, and AC-3's audit scope
is narrowed by this correction.** Appended rather than rewritten, per
`CLAUDE.md`'s append-only rule; the original text stands as the record of what
was claimed.

The cli package was named `@gitnebula/cli` until commit `efeaceb`
(`feat(cli): prepare the package for its first npm release`, PR #48,
2026-08-14 10:26:44 +0200 = 08:26 UTC) renamed it to `gitnebula`. Verified:
`git show efeaceb^:packages/cli/package.json` carries
`"name": "@gitnebula/cli"`, `git show efeaceb:packages/cli/package.json`
carries `"name": "gitnebula"`.

So the filter was **correct when the epic-3 and epic-4 stories ran**, and only
became a false green on 2026-08-14. Merge times against the rename:

| story | its work merged | vs rename (2026-08-14 08:26 UTC) |
| --- | --- | --- |
| 3.2-cli-serve-url | 2026-08-13 | before — command matched, suite ran |
| 3.6-fixture-build-race | 2026-08-13 | before — command matched, suite ran |
| 4.1-build-bundle | 2026-08-13 | before — command matched, suite ran |
| 4.6-docs-path-drift | 2026-08-14 07:44 UTC (PR #47) | before — command matched, suite ran |
| epic-4 retro addendum for 4.5 | 2026-08-14 08:37 UTC (PR #50) | the rename itself; documentation, not a suite claim |
| 5.5-viz-history-window | in flight, 2026-08-15 | **after — the only live false green** |

**Consequences for this story.** AC-1, AC-2, AC-5 and AC-6 are unaffected: a
filter that matches nothing must still fail, and the canonical commands must
still be written down once. **AC-3's audit is narrowed** to stories whose work
ran after 2026-08-14 08:26 UTC — on the evidence above that is 5.5 alone, and
the audit's honest finding may be "one story, caught before merge". The five
older occurrences are **stale today, not false when run**, and their correct
disposition is documentation rather than investigation.

The finding that produced this story is unchanged and still real: today the
command cannot fail, and a spec written tomorrow that copies it ships a test
gate that is decorative.
