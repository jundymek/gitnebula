## Story

As a developer opening a repository I have never seen,
I want the "start here" panel to name files that actually explain the code,
So that reading its five suggestions teaches me what the project does — not
that the project re-exports things.

## Context (binding)

- PRD FR-26; UX-DR6, UX-DR12, UX-DR14; NFR-12 (determinism); AD-1 (no new
  aggregation in the Viewer).
- **The finding, in the maintainer's words:** "tu mam indexy itp, nie widzę tu
  faktycznego zysku" — the panel lists index files and he cannot see what he
  gains from it.
- **This is not a defect in 5.1's implementation.** Its AC-1 says, literally,
  "ranked by in-degree descending", and the agent built exactly that. The
  wrong hypothesis was in the spec, so this is a deliberate change of the
  ranking rule and must be described as one.
- **The measurement**, on this repository (449 nodes) under the old rule. Four
  of `core`'s top five were barrels or leaves:

  | in-degree | loc | file |
  | --- | --- | --- |
  | 57 | 38 | `packages/contract/src/index.ts` |
  | 23 | 77 | `packages/viz/src/engine/index.ts` |
  | 22 | 158 | `packages/viz/src/engine/constants.ts` |
  | 22 | 29 | `packages/viz/src/test-support/fixtures.ts` |
  | 20 | 40 | `packages/cli/src/errors.ts` |

  About 340 lines between them, most of it `export * from`. Meanwhile
  `packages/viz/src/engine/engine.ts` — 1,694 lines, the heart of the product
  — ranked **ninth** and never appeared in the panel.
- **The diagnosis worth carrying:** in-degree measures *ubiquity*, not
  explanatory value, and in a workspace with barrel exports ubiquity
  concentrates precisely in the files that teach a newcomer nothing.

## Acceptance Criteria

- AC-1: `core` is ranked by **importers × lines of code**, descending, ties
  broken on `id` by code point. Supersedes 5.1's AC-1 `core` clause; the other
  two categories keep their out-degree rankings (FR-26).
- AC-2: On this repository, `core`'s top five contains no file whose content
  is predominantly re-exports, and contains `engine/engine.ts`. Asserted by a
  fixture reproducing the measured barrel-versus-engine case, which fails
  under the superseded rule.
- AC-3: The panel's `core` blurb states the rule, so a reader can explain the
  ordering from the row in front of them; each row prints both numbers the
  score is made of (UX-DR14's spirit: never a number whose meaning is
  guessable only).
- AC-4: Determinism is unchanged — no `localeCompare`, no clock, no RNG, ties
  on `id` by code point. The existing source-scan test keeps passing, and a
  genuine score tie is exercised by a fixture (the langgraph fixture's
  in-degree ties are separated by size under the new rule, so that coverage
  would otherwise have been lost silently).
- AC-5: The three categories stay disjoint by construction and the empty
  states keep story 5.5's conventions. No contract change; `schemaVersion`
  stays `"1.0"`.
- AC-6 (human-review): on a repository the maintainer knows, the five files
  `core` names are ones he would actually hand a newcomer. Recorded as an
  unticked item in `MANUAL_TESTING.md`.

### Debug Log References

- **Two rejected candidates, both by measurement rather than by argument.**
  Counting only non-test importers sounded principled — it should have dropped
  the test-fixture helper — but measured, it still put three barrels in the top
  five *and* demoted `engine.ts` further, because most of that file's importers
  are tests. Ranking by `importers × sqrt(loc)` kept two barrels in the top
  five, which fails AC-2's bar. Both are recorded because "we tried the
  obvious thing and it did not work" is the part that does not survive in a
  diff.
- **Checked against three repositories, not one**, to avoid tuning a rule to
  gitnebula's own shape: this repo, plus a 842-node and a 176-node real
  checkout. On the second the new rule drops a 2-line and a 3-line `index.ts`
  from the list; on the third it surfaces the actual data layer (832 lines) in
  place of a 31-line logger.
- **A green suite hid a red compiler again, in the same way as 5.6.** The new
  fixtures built edges without the contract's `kind: "import"`; `vitest` does
  not type-check, so lint, test and build were green while `tsc --noEmit`
  failed with TS2322. Second time this exact gap has bitten on this branch —
  `pnpm -r typecheck` belongs in the loop, not at the end of it.
- **Two older tests kept passing while describing a rule that no longer
  exists.** The langgraph fixture's order is coincidentally unchanged, so
  "ranks core by in-degree descending, ties broken on id" was green and wrong.
  Renamed and re-commented; a suite that documents a false rule is worse than
  a red one.

### Completion Notes List

- The rule is `inDegree × loc`. Both factors are needed: in-degree alone
  crowns barrels (the finding), size alone crowns whatever is longest whether
  or not anything depends on it — measured, that put a 906-line stylesheet in
  `core`.
- **Barrels are demoted, not filtered.** A filter would have to decide what a
  barrel *is*, and the contract carries no such fact — only `loc`, which is
  the honest proxy. A file that everything imports is still worth being able
  to see.
- Still selection and sorting, not a new aggregation (AD-1): `loc` is a
  contract field and in-degree is a count of contract edges, exactly as 5.1
  already counted them.
- The weakest remaining entry on this repository is
  `packages/cli/src/test-support.ts` (12 importers × 216 lines) — test
  scaffolding that lives in `src/`, so no layer rule excludes it. Left as is:
  excluding it would need a heuristic on file names, which is the kind of rule
  that breaks on the next repository.
- Not done: no browser rendered the panel. No browser extension is connected
  in this environment, so AC-6 and the visual check stay unticked with the
  reason stated.
