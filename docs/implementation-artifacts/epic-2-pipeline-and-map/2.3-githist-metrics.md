## Story

As a developer hunting hot spots,
I want churn, authors and co-change computed from local git history,
So that the map shows where things happen, deterministically.

## Context (binding)

- PRD FR-10; ADR-0003 (churn = `min(1, commits / P95(commits))` over
  same-kind nodes with ≥1 commit; module commits counted DIRECT — a commit
  touching 3 files of one module = 1; window-neutral field names), ADR-0005
  (cochanges bounded: count ≥ 3, top 500 per kind; module pairs aggregated
  HERE), AD-13 (`windowAnchor` from Config — never read the clock; one-pass
  `git log -M --name-status`; `--follow` is banned; drop+count paths outside
  the ScanResult universe), AD-14 (test against the built fixture repo).
- Your only side effect is spawning `git` (AD-3). Parse porcelain-stable
  output (`-z` where sensible).

## Acceptance Criteria

- AC-1: One `git log` pass over the window (`--since` derived from
  `windowAnchor` − `windowDays`) with `-M --name-status` yields per-node
  `commits` (module counting direct), distinct `authors`, max
  `lastChangedAt` (ISO UTC), with renames mapped old→new so a renamed
  fixture file keeps its pre-rename counts.
- AC-2: `churn` per ADR-0003 with P95 computed over same-kind nodes with
  ≥ 1 commit; zero-activity nodes get 0; a single-node kind gets churn 1.0
  for that node (P95 of one value = itself) — covered by a test.
- AC-3: Co-change pairs from multi-file commits: file-file and aggregated
  module-module, `count ≥ 3` only, top 500 per kind, stable sort (count
  desc, then ids); commits touching > 50 files are skipped for co-change
  (bulk-change noise) and counted as a warning.
- AC-4: Zero commits in window → all `churn: 0`, no NaN/division error.
- AC-5: Paths in history absent from the ScanResult universe are dropped and
  counted (AD-13).
- AC-6: Snapshot vs the fixture repo (pinned `windowAnchor`) matches
  committed expected values exactly; byte-identical across runs.

### Debug Log References

- **Rename mapping failed against real git, passed against synthetic input.**
  The `-z` framing puts a newline between the commit header and the first
  status token, so git emits `"\nR100"` where the hand-written parser fixtures
  had `"R100"`. The rename branch therefore never fired: the record was read as
  two single-path entries, the alias was registered backwards, and
  `core/score.py` was dropped as outside the universe three times while
  `core/scoring.py` reported one commit instead of four. Fixed by trimming the
  status token, and the parser fixtures were corrected to reproduce the real
  framing — the bug existed precisely because they did not.
- Key assertions were mutation-checked before being relied on: perturbing the
  P95 rank and the 50-file bulk threshold turned four tests red, including the
  fixture snapshot; reverting turned them green again.
- **Record framing was unsafe for a legal filename.** The parser split the
  whole stream on the 0x1e record separator, but POSIX forbids only NUL and `/`
  in a path, so a tracked file whose name contains 0x1e would be torn in half
  and its tail read as a spurious commit — corrupting that commit and the one
  after it. Raised by Codex review. The parser is now a state machine over
  NUL-separated tokens that tests for a leading 0x1e only where a header may
  begin; path tokens are consumed positionally and never inspected. Covered by
  parser tests and by an end-to-end test against a real repository carrying
  such a filename.

### Completion Notes List

- One `git log -M -z --name-status` pass per run, bracketed by
  `--since`/`--until` derived from `Config.windowAnchor`. No clock, no
  randomness, no per-file invocation; `--follow` is absent and the README
  records the three reasons AD-13 bans it.
- IO and rules are separated: `readGitLog` spawns git, `computeGitResult` is
  pure. Every AC except the fixture snapshot is asserted without a repository.
  67 tests, all green, plus `pnpm lint` and `pnpm -r typecheck`.
- Committer date is used for both the window filter and `lastChangedAt`.
  `--since`/`--until` filter on committer date with no author-date equivalent,
  so reporting author dates would let a node's timestamp fall outside the
  window that selected it. Identical on the fixture, where both are pinned.
- **Reversed under review: merges stay in the log.** The first implementation
  passed `--no-merges`, on the reasoning that a merge prints no file records
  and so attributes to nothing. Two Codex findings pushed back and were right:
  `GitResult.commits` is documented as the repo-wide count and feeds
  `repo.stats.commits`, so redefining it to "commits that changed files" bent a
  merged contract field to suit the implementation. Measured on this repository,
  which merges epic branches: 20 commits in a 400-day window, 19 with
  `--no-merges` — the undercount was observable on gitnebula itself, and
  `lastCommitAt` could have gone stale whenever the newest commit in a window
  was a merge. Merges now count repo-wide and attribute to no node; a
  changeless `--allow-empty` commit behaves the same way and needs no warning,
  having no paths to drop. arnold was sent a correction, since the original
  reasoning had already been relayed.
- Deviation from the literal reading of `GitResult.history` ("nodes absent from
  the map have no history"): an entry is emitted for **every** node in the
  universe, untouched ones carrying explicit zeros and `lastChangedAt: null`.
  AC-4 asks for `churn: 0` on all nodes and the contract requires the four
  fields on every node, so this removes an invent-a-default decision from cli.
  No node is absent, so the documented behaviour is not contradicted.
- The `analyze` input envelope is `{ root, scan }`, declared in this package —
  the contract exports result shapes, not input shapes. Field named `root`
  rather than `repoRoot` to match the wrapper deps settled on, after arnold
  asked (`from-arnold-001`); confirmed back in `to-arnold-001`.
- Churn is reported at 3 decimals, matching the committed contract fixtures,
  with a 0.001 floor for any node that has activity so `churn === 0` keeps
  meaning "no commits in the window". P95 uses the nearest-rank estimator,
  which is what makes a single-node kind resolve to exactly 1.0 (AC-2).
- **Observation for the human-review checklist, not a defect:** the fixture
  repo's only repeated co-change pair has count 2, under ADR-0005's `count >= 3`
  bound, so `cochanges` is legitimately empty in the AC-6 snapshot and will be
  in 2.4's end-to-end snapshot too. `build-fixture-repo.sh` was deliberately
  left untouched — changing it would move commit hashes under stories 2.1 and
  2.4 mid-wave. AC-3 is covered by unit tests over the pure pair extractor,
  whose input shape is pinned to real `git log` output by the parser tests. If
  the maintainer wants co-change exercised end to end, that is a follow-up
  story adding a sibling fixture repo, not an edit to this one.
- The 1.1 scaffold export `contractEdge` is retired, as its comment instructed,
  now that this package imports real contract types. `packageName` stays: cli's
  package-wiring test consumes it.
