## Story

As a developer exploring a TS/JS repo,
I want import statements resolved to real repo files,
So that edges reflect actual dependencies, not guesses.

## Context (binding)

- PRD FR-11; ADR-0001 (TypeScript compiler API — `ts.resolveModuleName`
  against the repo's own tsconfig; this is WHY tree-sitter was rejected for
  TS), AD-1/ADR-0005 (module-level edges aggregated HERE, weight = file-pair
  count), AD-3 (signature/purity), AD-7 (drop + count, never throw), AD-13
  (resolve only within the ScanResult universe).
- Input: `ScanResult` (from contract types) — you parse only files it lists.

## Acceptance Criteria

- AC-1: Crafted TS fixture resolves correctly: relative imports, `paths`
  aliases (`@/…`), `baseUrl`, `index.ts` implicit imports, re-export chains
  (`export * from`), dynamic `import()` with literal specifiers, JS
  `require` with literal specifiers.
- AC-2: Imports resolving into `node_modules` or outside the ScanResult
  universe produce no edge and increment the proper counter (distinct codes:
  `external`, `outside-universe`, `unresolved`).
- AC-3: File-level edges are deduplicated per (source,target); module-level
  edges aggregate with `weight` = count of underlying file pairs; both
  levels stably sorted.
- AC-4: A file with syntax errors yields no edges + one counted warning; the
  stage completes (AD-7).
- AC-5: Snapshot test vs the fixture repo matches committed expectations;
  byte-identical across runs.
- AC-6: Local run against excalidraw (pinned SHA in your notes): unresolved
  rate recorded in docs README and ≤ 20% (FR-11 threshold).
- AC-7: A repo with no tsconfig.json parses with default resolution (no
  crash, relative imports still resolve).

### Debug Log References

- **The excalidraw measurement failed first, at 21.2% unresolved** — over the
  FR-11 threshold — with `external: 0`, which was the tell. A one-off diagnostic
  broke the 904 failures down: 587 bare specifiers (`react`, `clsx`, `node:fs`)
  failing only because a bare clone has no `node_modules`, and 317 relative
  asset imports (230 `.woff2`, 83 `.scss`, 4 `.css`). Not one genuine miss. The
  classification changed in response, never the threshold. Final: 0 of 4,261.
- **Classifying externality before universe membership dropped workspace
  edges.** In a pnpm workspace an intra-repo package resolves *through* a
  `node_modules` symlink to a repo file. Verified on this repository:
  `packages/deps` to `packages/contract` — the AD-2 edge the architecture
  declares — appears only with universe membership checked first.
- `ts.createSourceFile` never throws on a broken file; AC-4 needed the internal
  `parseDiagnostics` array, read defensively.
- Every assertion was seen red before being trusted: removing the fixture's
  `tsconfig.json` (5 red, unresolved 1 to 5), renaming the `parseDiagnostics`
  internal (5 red), removing pair deduplication (6 red).

### Completion Notes List

- All seven ACs are covered by executable tests except AC-6, a local
  measurement whose numbers and reproduction command are in the docs README.
  `pnpm --filter @gitnebula/deps test`: 24 passed, 1 skipped (the opt-in
  measurement). `pnpm lint`, `pnpm typecheck`, `pnpm test` (183) all exit 0.
- **Divergence from the spec, flagged.** `analyze` takes `{ root, scan }`, not
  a bare `ScanResult`: `ScannedNode.path` is repo-relative and `Config` carries
  no root, so a bare `ScanResult` cannot be opened, and adding a root to the
  contract would be a contract change — which CLAUDE.md forbids as a side
  effect of another story. `DepsInput` is deps-local; `DepsResult` and all edge
  types are unchanged contract types. cli's agent was messaged directly.
- **Divergence from AC-2, flagged.** AC-2 says imports resolving into
  `node_modules` produce no edge. Universe membership is checked first, so an
  intra-repo workspace package reached through a `node_modules` symlink does
  produce an edge — otherwise gitnebula would draw its own monorepo with no
  package dependencies at all.
- Warning codes are `external-import`, `outside-universe-import`,
  `unresolved-import` and `unparsable-file`: AC-2's three distinctions, in the
  naming style the contract's own `AnalyzerWarning.code` documentation uses.
- Type-only imports are edges (architectural dependencies); computed specifiers
  are skipped without being counted (there is no import string to resolve).
- The crafted fixture is built by a new sibling script into the gitignored
  `.generated/`, per AD-14. githist's `build-fixture-repo.sh` was deliberately
  not touched — its commit hashes are pinned by story 2.3's snapshots.
- The collect/resolve split is the seam story 3.1 needs: a Python parser adds a
  sibling pair of modules and reuses `edges.ts` and `warnings.ts` unchanged.
- Known limitation, recorded in the docs README rather than papered over: a repo
  importing its own source through a bare specifier with no `paths` entry and no
  install is counted external, so that edge is missed until the workspace is
  installed.
