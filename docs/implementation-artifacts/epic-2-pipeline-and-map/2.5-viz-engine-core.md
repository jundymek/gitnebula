## Story

I want the nebula to render, settle and respond at the mockup's exact look,
So that the first view already delivers the wow.

  layout+render behind ONE interface; chrome talks only to it), AD-6
  (seeded PRNG from `hash(repo.name)`; Settled = max displacement

## Acceptance Criteria

- AC-1: Vite dev serves a chosen contract fixture at `./analysis.json`
  (mechanism documented); the viewer fetches only that URL; a fixture with
  major version ≠ `SUPPORTED_SCHEMA_MAJOR` renders a clear error screen
  naming both versions (FR-6).
- AC-2: On load, nodes appear and visibly settle; Settled reached in 2–3 s
  on the 100-module fixture (automated: displacement-based, from first
  render); camera then fits the graph ≤ 800 ms; a replay control re-runs
  it; layout is identical across reloads (seeded); `prefers-reduced-motion`
  renders pre-settled (FR-12, AD-6).
- AC-3: Encoding matches the mockup exactly: palette hexes (#3fcfa0/
  #9b8cff/#7c8598/#a8cf52/#ff7a3d on #060911), node radius ∝ √LOC, glow
  radial gradient ∝ churn, hot nodes (churn ≥ configured threshold, default
  0.5) render `--hot` REPLACING layer colour and pulse ~380 ms (still under
  reduced-motion), starfield ~220 stars two sizes, module labels above
  nodes, curved translucent edges (FR-13, UX-DR1–5).
- AC-4: Chrome: header (brand, repo name, stats bar with name/files/LOC/
  modules/commits/languages), legend (4 layers + hot spot), bottom-right
  hint overlay — all per mockup layout; module count derived from nodes
  (FR-13, UX-DR6/9).
- AC-5: Drag pans; scroll zooms cursor-centred, clamped [0.4, 6.0]; grab/
  grabbing cursors (FR-15, UX-DR10).
- AC-6: Structural rule holds: chrome modules import the GraphEngine
  interface only — no canvas/context/simulation access outside the engine
  implementation (enforced by directory structure + a lint boundary or a
  test that greps imports; document which).
- AC-7: The GraphEngine interface (load/seed/events/camera/pick/mode/
  highlight/exportPNG) is defined in full even where this story implements
  only part — 3.3/3.4/3.5 build against it unchanged (their specs are
  frozen against your interface; changing it later = coordination cost you
  personally caused).

### Debug Log References

- **Settle timing had to be tuned against two bounds, not one.** The first
  tuning reached Settled in 210 frames (3.5 s), outside AC-2's 2–3 s. Raising
  `alphaDecay` alone plateaued at ~165 frames — the tail is the collide/link
  relaxation, not alpha — so charge and link distance moved too. The committed
  constants settle in **148 frames ≈ 2.47 s**.
- **The zoom clamp constrains the layout.** With the looser tuning the settled
  graph spanned ≈1500 × 1620 world px, which a 1200 × 800 viewport cannot frame
  above FR-15's 0.4 zoom floor — `fit()` clamped and the graph overflowed the
  screen. Caught by an engine test asserting the fitted zoom is strictly above
  the floor. Committed bounds: ≈1080 × 1086, fitting at ≈0.57×.
- **Camera flights were timed against the wrong clock.** `fit()` stamped
  `performance.now()` at creation while the loop advanced it on the rAF
  timestamp; in the browser those share an origin so it worked, and under test
  `t` went negative and the flight never advanced. Flights now stamp their start
  on their first animated frame, which is clock-agnostic.
- **d3-force needs `randomSource`, not just seeded positions.** `forceManyBody`
  and `forceLink` call `jiggle()` — an unseeded `Math.random()` — whenever two
  nodes coincide. Seeding only the initial scatter would have left a
  determinism hole that appears rarely and is impossible to reproduce.
- **The boundary test was watched fail** before being relied on: adding
  `import { LAYER_COLOR } from "../engine/constants.js"` to `chrome/hint.ts`
  turns it red with "imports an engine internal instead of the barrel".
- **Browser verification** (Chrome, dev server, `synthetic-100x2000`): settles
  and fits; drag pans one-to-one; wheel zooms cursor-centred; a `schemaVersion`
  `99.0` document renders the refusal screen naming `99.0` and `1`; no console
  errors. A locally modified mixed-churn copy of the fixture rendered the full
  layer palette, confirming the all-orange default map is the data, not the
  encoding.

- **Codex review: 3 findings, all fixed, none dismissed.** (P1) A document
  declaring a supported major but missing the rest of the contract passed the
  version gate and then blanked the page on `repo.name`; the loader now
  structurally checks the fields the Viewer dereferences and routes failures to
  the malformed screen — a shape guard rather than in-browser ajv, which would
  pull the validator and the schema into the bundle to re-check what the
  pipeline validates at emit time. (P2) `setCamera` stored a `k` outside
  [0.4, 6.0], which picking and panning then divide by; it clamps now, and
  `clampZoom` sends NaN to the floor while letting the infinities clamp to the
  correct end. (P2) `panBy`/`zoomAt` dropped a running `fit()` flight without
  resolving its promise, hanging anything awaiting the camera; a single
  `cancelFlight()` resolves-then-clears and is used by pointer input, `replay()`
  and `destroy()`. Each fix carries a regression test.
- **Codex re-review: 1 further finding, fixed.** (P1) `jsdom` had been added at
  version 30, whose engines are `^22.22.2 || ^24.15.0 || >=26.0.0`, while the
  workspace declares Node `>=20.19` and `.github/workflows/ci.yml` runs Node 20
  — it installed and tested fine locally and would have broken on the supported
  runtime. Pinned to `jsdom@^27.4.0` (engines `^20.19.0 || ^22.12.0 ||
  >=24.0.0`), with its dependency tree walked to confirm nothing else asks for
  Node 22. The lockfile was regenerated from the epic branch's copy rather than
  patched: adding then removing jsdom 30 left its peer resolution attached to
  five unrelated packages' `vitest` entries, keeping the bad version in the
  lockfile after `viz` stopped asking for it.
- **Codex third pass: 2 further findings, both fixed.** (P2) `parseInt` reads a
  *prefix*, so `1garbage` and `1.x` both parsed as major 1 and passed the
  compatibility gate as if they were `1.0`; the version is now matched whole
  against `<integer>.<integer>`. The first version of that test did not
  discriminate — the shape guard rejected those documents for having no
  `nodes`, so it passed against the old parser too; rewritten to vary only the
  version on an otherwise complete document, it fails on four of six cases
  against the old parser and passes against the fix. (P2) `nodes: [null]`
  passed an `Array.isArray` check and then threw inside `buildGraph`; the guard
  now checks the elements, and `boot()` additionally converts any engine
  construction failure into the FR-6 screen, so a structural surprise the guard
  does not model still cannot blank the page.

### Completion Notes List

- All seven ACs implemented. 148 tests in `@gitnebula/viz`; `pnpm lint`,
  `pnpm test` and `pnpm --filter @gitnebula/viz build` all exit 0.
- **AC-6 is enforced by a test, not a lint plugin** — the spec allowed either
  and asked which. `src/chrome/boundary.test.ts` checks both halves of the rule
  (no reaching past `engine/index.ts`, and no canvas/context/simulation
  reference at all), plus the mirror rule that the engine never imports chrome,
  plus that `d3-force` is imported by exactly one engine module. A lint
  boundary plugin would express only the import half and would add a
  dependency for one rule.
- **AC-7: the interface is complete; two members reject by design.** `flyTo`
  and `exportPNG` return promises rejecting with the owning story id
  (`3.3-viz-navigation`, `3.5-viz-export-perf`). `unfoldedModules()` and
  `isUnfolded()` answer truthfully rather than throwing — in 2.5 nothing is
  unfolded, and that is the correct answer, not a stub.
- **Mode and highlight state are implemented; their inputs are not.**
  `setMode`, `setHovered`, `setSelected`, `setIsolated` and `chainOf` carry
  state, emit events and drive the renderer's chain/dim paths, so 3.3/3.4 build
  against a real seam. Hover picking, the tooltip, click-to-select, the mode
  toggle and isolate stay in their territory; the header renders empty
  `#mode-slot` and `#export-slot` containers for them (3.5's spec asks for the
  export slot to exist since 2.5). Disabled buttons that never enable would be
  a lie in the UI.
- **2.5 simulates and draws modules only.** `buildGraph` builds the whole node
  set, the member index and the file-level edges — story 3.3 needs all of it —
  but only module nodes enter the simulation and the renderer. Unfold is
  ADR-0006 and story 3.3.
- **The hot threshold is a viz-side constant** (`HOT_THRESHOLD = 0.5`, override
  via `EngineOptions.hotThreshold`). The pipeline's `hotspotThreshold` lives in
  the resolved `Config` and never reaches `analysis.json`, so the Viewer cannot
  read it; wiring it through would be a contract change, which is never a side
  effect of another story.
- **Deviation from the mockup, deliberate:** language shares print the
  contract's names (`typescript 74% · python 26%`) rather than the mockup's
  hardcoded `py`/`ts` abbreviations. The contract carries no abbreviation table
  and inventing one in `viz` would put analyzer knowledge in the frontend
  (AD-1).
- **Deviation from the mockup, deliberate:** file radii come from the
  contract's LOC via the same `√LOC` term as modules, where the mockup jittered
  them randomly. AD-6 puts all randomness in one seeded stream.
- **The loader gates on the version only**, not the full schema — AD-12 and
  AC-1 ask for the major check and the FR-6 screen, and running ajv in the
  browser would pull the validator and schema into the bundle for a check the
  pipeline already performs at emit time.
- **Two dev dependencies added to `viz`**, no runtime ones: `jsdom@^27.4.0`
  (chrome and engine tests need a DOM; pinned below 30 for Node 20 support —
  see the debug log) and `@types/node` (the test-only fixture loader
  reads the committed contract fixtures from disk, as the contract's own
  fixture test does).
- **Finding for a follow-up, not fixed here:** all 100 modules of
  `synthetic-100x2000.json` have churn ≥ 0.797, so structure mode paints the
  entire map `--hot` and the four layer colours never appear on that fixture. No
  committed fixture exercises the layer palette together with hot spots, which
  stories 3.3/3.4 will want. Fixtures are story 1.3's territory and a frozen
  artifact, so this is reported rather than changed.
