## Story

As a developer running gitnebula,
I want the repo tree scanned into classified, measured nodes,
So that every downstream stage works from one closed universe.

## Context (binding)

- PRD FR-9; AD-3 (signature `analyze(input, config, onProgress?)`; exclude
  and layer-rule *data* exported by you, *resolution* by cli), AD-4
  (determinism, no clock/random), AD-13 (your `ScanResult` is the closed
  universe; picomatch, only here), ADR-0002 (layer rule table + override
  semantics: user rules prepended, first match wins, test-detection first,
  module layer = dominant by LOC).
- Module derivation: top-level dirs; if one dir holds > 80% of analyzable
  files, descend one level; max depth 2 (PRD assumption — validate against
  demo repos and tune; record the final thresholds in your docs README).
- Types come from `@gitnebula/contract` (merged) — do not redefine.

## Acceptance Criteria

- AC-1: `analyze` walks the tree honoring excludes from passed config
  (defaults exported as `DEFAULT_EXCLUDES` data covering at minimum:
  `node_modules`, `.venv`, `venv`, `dist`, `build`, `.git`, lockfiles,
  `*.min.js`, `*.map`, binary assets, `_bmad`, `.claude`), producing a
  `ScanResult` with per-file LOC, language, layer, and module assignment.
- AC-2: Layer table is an exported ordered data structure; test-detection
  precedes all; unmatched → `other`; `layers:` config globs prepend and win;
  module layer = dominant member layer by LOC (ADR-0002).
- AC-3: Module derivation implements the descent heuristic; a crafted
  fixture with 95% of files under `src/` yields `src/`-level modules; depth
  never exceeds 2.
- AC-4: Snapshot test against the built fixture repo (`test-fixtures/`)
  matches committed expectations; two runs byte-identical (stable ordering).
- AC-5: Unknown-language files are counted in LOC/stats and layered `other`;
  language shares sum to 1 (±ε) over analyzable files.
- AC-6: Run locally against the three demo repos; record module/layer output
  summary in your docs README for the human-review checklist (not a test —
  evidence for 4.4).
