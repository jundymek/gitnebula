## Story

As a developer running gitnebula,
I want the repo tree scanned into classified, measured nodes,
So that every downstream stage works from one closed universe.

## Context (binding)

- PRD FR-9; AD-3 (signature `analyze(input, config, onProgress?)`; exclude
  and layer-rule *data* exported by you, *resolution* by cli), AD-4
  (determinism, no clock/random), AD-13 (your `ScanResult` is the closed
  universe; picomatch, only here), ADR-0002 (layer rule table + override
  semantics: user rules prepended, first match wins, test-detection first,
  module layer = dominant by LOC).
- Module derivation: top-level dirs; if one dir holds > 80% of analyzable
  files, descend one level; max depth 2 (PRD assumption — validate against
  demo repos and tune; record the final thresholds in your docs README).
- Types come from `@gitnebula/contract` (merged) — do not redefine.

## Acceptance Criteria

- AC-1: `analyze` walks the tree honoring excludes from passed config
  (defaults exported as `DEFAULT_EXCLUDES` data covering at minimum:
  `node_modules`, `.venv`, `venv`, `dist`, `build`, `.git`, lockfiles,
  `*.min.js`, `*.map`, binary assets, `_bmad`, `.claude`), producing a
  `ScanResult` with per-file LOC, language, layer, and module assignment.
- AC-2: Layer table is an exported ordered data structure; test-detection
  precedes all; unmatched → `other`; `layers:` config globs prepend and win;
  module layer = dominant member layer by LOC (ADR-0002).
- AC-3: Module derivation implements the descent heuristic; a crafted
  fixture with 95% of files under `src/` yields `src/`-level modules; depth
  never exceeds 2.
- AC-4: Snapshot test against the built fixture repo (`test-fixtures/`)
  matches committed expectations; two runs byte-identical (stable ordering).
- AC-5: Unknown-language files are counted in LOC/stats and layered `other`;
  language shares sum to 1 (±ε) over analyzable files.
- AC-6: Run locally against the three demo repos; record module/layer output
  summary in your docs README for the human-review checklist (not a test —
  evidence for 4.4).

### Debug Log References

- The first green run proved nothing on its own, so five deliberate mutations
  were introduced and reverted to confirm the suite can fail: descent threshold
  0.7 to 0.99 (4 tests red), user layer overrides appended instead of prepended
  (3 red), binary detection disabled (1 red), and the blank-line rule inverted.
  That last mutation passed at first — the LOC tests only used *empty* lines,
  which never count either way — so a whitespace-only-line case was added and
  the mutation then failed as it should.
- Demo-repo tuning runs (fastapi, excalidraw, streamlit at `--depth 1`) were
  driven by throwaway scripts in the session scratchpad; nothing from them is
  committed. Their measurements are in the story README.
- Removing the story-1.1 `packageName` stub from `@gitnebula/scanner` broke
  `packages/cli` typecheck, which still imports it. The export was kept and
  documented as the 1.1 seam rather than editing cli, which belongs to 2.4.

### Completion Notes List

- `analyze({ root }, config, onProgress?)` implements AD-3 exactly: no config,
  environment, clock or network reads. `DEFAULT_EXCLUDES` and `LAYER_RULES` are
  exported as data for cli to resolve against. The signature was agreed with
  arnold (2.4) by peer message before implementation, and mirrors bob's (2.2).
- **Divergence from PRD FR-9, deliberate and sanctioned:** the module descent
  threshold is **0.7**, not the PRD's 0.8. The PRD marks that number an
  assumption to be refined against the demo repos and this story's Context says
  to tune and record. At 0.8 excalidraw's `packages/` (79.2% of files) misses
  the bar and the repository draws as one 228k-line module; at 0.5 fastapi's
  `docs/` shatters into thirteen translation modules. 0.7 and 0.6 give identical
  output on all three repos. Depth 2 is unchanged. Full numbers in the README.
- Three excludes added on the same evidence (`**/__snapshots__`, `**/*.snap`,
  `**/.yarn`) — AC-1 calls its list a minimum and all three are machine-written
  artifacts. One layer rule removed (`**/testing/**`), which was labelling
  streamlit's shipped `lib/streamlit/testing/` public API as test code.
- Judgement calls not fixed by a spec, each recorded in `DECISIONS.md`: LOC is
  physical lines carrying non-whitespace; language shares are over analyzed
  *lines* (the contract's wording) with unrecognized extensions bucketed as
  `unknown`; repository-root files carry `parent: null` rather than joining a
  synthetic root module; a descended directory survives as a module for its own
  direct files; `.gitignore` is not consulted (AD-3 forbids the side-door read).
- AC-6 raises one item for the 4.4 human-review checklist rather than a bug:
  streamlit's `frontend/` and `lib/` both resolve to layer `test`, because that
  repository genuinely has more test lines than source lines in both trees.
  That is ADR-0002's stated dominance rule working as decided; changing it would
  be an ADR revision and its own story.
- Codex review ran to four passes and returned four P2 findings, all fixed. (1) On filesystems
  answering `DT_UNKNOWN` every `Dirent` predicate is false, so the walk wrote
  ordinary files off as irregular and could skip a whole repository — fixed
  with an `lstat` fallback in `classifyEntry`. (2) The LOC rule says
  whitespace-only lines do not count, but only ASCII whitespace was
  recognized, so a line holding one no-break space counted as code — the
  counter now recognizes the byte sequences the Unicode spaces encode to,
  across chunk boundaries, without decoding UTF-8 in the hot loop. (3) A bare
  carriage return was blank filler rather than a line ending, so a pre-OS X
  Mac file counted as one line however long it was. (4) Glob matching was
  case-sensitive, so `logo.PNG` survived the binary-asset exclusions.
- Fixing (3) turned up dead code by way of a mutation test: the CRLF special
  case could be deleted without a single test going red, because the
  zero-length line between CR and LF carries no content and lines with no
  content are never counted. It was removed rather than kept for reassurance.
- Verified: `pnpm lint` and `pnpm test` both exit 0 across the workspace
  (145 scanner tests). Demo-repo output is byte-for-byte what the README
  records — re-measured after the last fix. `pnpm build` not run — this story touches neither `cli`
  nor `viz`.
