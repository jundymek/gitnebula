## Story

As a developer in a repo directory,
I want one command that runs the staged pipeline and emits a valid `analysis.json`,
So that analysis works end-to-end with visible progress.

## Context (binding)

- PRD FR-1 (analysis half), FR-3, FR-4, FR-7, FR-8; AD-3 (config resolution
  lives HERE: defaults < `.gitnebula.yml` < flags; analyzers get plain
  values), AD-4 (you inject `analyzedAt` + `windowAnchor`), AD-7 (failure
  shape `«stage»: «cause» — «remedy»`), AD-10 (llm key notice + `enrich`
  identity hook), AD-13 (anchor), ADR-0002 (scanner exports exclude/layer
  data — you merge user config over it).
- The pipeline: `scan → (deps ∥ githist) → assemble + validate → enrich →
  emit`. Assemble merges results and runs `validateAnalysis`; it does NOT
  aggregate (analyzers did).

## Acceptance Criteria

- AC-1: Config resolver: defaults < `.gitnebula.yml` < CLI flags; supports
  excludes, windowDays, layers, hotspotThreshold, llm (passthrough); invalid
  config fails fast naming key and line; the llm key prints exactly one
  ignored-in-MVP notice (FR-4, AD-10).
- AC-2: Each stage prints a start line and an end line with elapsed time;
  `onProgress` from analyzers renders within-stage counts; a stage failure
  exits non-zero with the AD-7 shape (test: point it at a non-git dir).
- AC-3: Emitted `analysis.json` passes `validateAnalysis`; `analyzedAt` and
  `windowAnchor` are injected here and nowhere else; two runs on the fixture
  repo differ only in `analyzedAt` (byte-compare test with anchor pinned via
  flag).
- AC-4: `enrich(analysis)` identity hook sits between validate and emit;
  with no llm config: no warnings, no output degradation (FR-8).
- AC-5: End-to-end on the built fixture repo with ALL THREE analyzers wired:
  emitted file's snapshot matches committed expectations — this is the M2
  evidence; quote the test's summary line in the PR body.
- AC-6: A `--window-anchor <iso>` (or equivalent hidden flag) exists for
  deterministic testing and is documented as test-only.

### Debug Log References

- **The built binary crashed on its first import once `deps` was wired.** The
  TypeScript compiler API `deps` uses for module resolution (ADR-0001) is
  CommonJS; inlining it into the ESM tsup bundle produced
  `Dynamic require of "fs" is not supported`, and then
  `ERR_AMBIGUOUS_MODULE_SYNTAX` once a `require` was shimmed in via
  `createRequire`. Resolved by marking `typescript` external and declaring it a
  runtime dependency of `@gitnebula/cli`; bundle 9.9 MB → 389 KB. No test
  caught this, because every suite runs from source where the compiler API
  loads fine — flagged for story 4.1 (see Completion Notes).
- **A stage-order test encoded a race.** It asserted `deps` then `githist` in
  the completed-stage list. They run concurrently, so that only held while one
  of them was still a stub; wiring the real scanner made `deps` slower and the
  test failed. It now asserts that both sit between `scan` and `assemble`, plus
  a separate test that both start lines precede either end line. Verified red
  by making the pipeline sequential.
- **`pnpm test` at the workspace root is flaky, and it is not this story's
  defect.** `packages/contract`, `packages/scanner` and `packages/githist` each
  invoke `test-fixtures/build-fixture-repo.sh` from inside their own tests; the
  script begins with `rm -rf`, and `pnpm -r test` runs packages in parallel, so
  one package deletes the fixture repository while another reads it. Evidence:
  a scratch worktree at the unmodified epic head `bb45e91` — none of this
  story's commits — fails 3 runs out of 3, alternating between `scanner` and
  `githist` with `Error: Command failed: sh …/build-fixture-repo.sh`. Every
  package passes in isolation, including this one. Worked around rather than
  fixed: cli's `pretest` builds the fixture repo only when it is absent, so
  this package stays out of the race. The real fix — one build owned by the
  root `pretest`, the three in-test rebuilds removed — spans three merged
  stories and is reported to the supervisor.
- **Codex review raised two real defects, both fixed.** (1) `commander@15`
  declares `engines.node >= 22.12`, but the workspace floor is Node 20.19 —
  pinned back to `^14.0.3`, whose floor is Node 20. (2) A local directory whose
  first path component looks like a host, such as `example.com/checkout`, was
  refused as URL mode without checking the filesystem; target classification
  now prefers an existing local path, and only an unambiguous scheme or
  scp-style spec is remote regardless.
- **Found while walking the security checklist:** a mistyped path reported
  `git is not available on PATH`, because a missing `cwd` and a missing `git`
  binary both surface as ENOENT from `execFileSync`. The repo stage now stats
  the target first and distinguishes "does not exist", "is not a directory" and
  "is not a git repository". All three fixes were verified red before green by
  mutating the implementation back.
- The config resolver's line numbers were verified red by stubbing `lineOfKey`
  to return 1 — three tests fail, so the reported line is genuinely read from
  the YAML AST rather than guessed.

### Completion Notes List

- **All six ACs are met.** AC-5's summary line:
  `history-repo: 3 modules, 3 files, 0 edges, 0 co-change pairs, 5 commits in 365d`.
- **Two empties in that snapshot are correct.** Co-change is empty because the
  fixture's only repeated pair appears in 2 commits and ADR-0005 admits pairs
  at `count >= 3`; `build-fixture-repo.sh` was deliberately not extended,
  because its commit hashes are pinned by 2.1's snapshots and by this one.
  Edges are empty because the fixture's two code files import nothing — import
  resolution is covered by deps' own fixtures.
- **Deviation: two stages precede the architecture's `scan`.** The pipeline is
  `repo → config → scan → (deps ∥ githist) → assemble+validate → enrich →
  emit`. `repo` and `config` are preconditions for `scan`, not new pipeline
  filters: the analyzers need an absolute repository root and a resolved
  `Config`. `repo` doubles as the non-git-directory preflight AC-2 asks for.
- **Deviation: `repo.name`, `remoteUrl` and `defaultBranch` are read by `cli`.**
  The contract requires them and no `*Result` carries them. `cli` is the only
  composer (AD-2) and is exempt from AD-4's clock ban, so it runs `git rev-parse`,
  `git remote get-url origin` and `git symbolic-ref` itself. The alternative —
  widening a merged contract type — is forbidden as a side effect of another
  story.
- **`typescript` became a runtime dependency of `@gitnebula/cli`** (see Debug
  Log). AD-11 requires the bundle to inline all *workspace* packages, which it
  still does; a third-party CommonJS dependency staying external does not
  contradict it.
- **Finding for story 4.1 (build-bundle), not fixed here:** nothing in any
  suite executes `dist/gitnebula.js`, which is why the bundle defect above
  reached a built artifact undetected. 4.1 should add a smoke test that runs
  the built binary. Not added here because `pnpm test` does not build `dist`,
  and a test that silently skips when the bundle is absent is worse than none.
- **Observation, not acted on:** running against this repository classifies the
  `packages/` module as `test` (dominant layer by LOC, ADR-0002) because the
  colocated `*.test.ts` files outweigh the sources. That is scanner's rule
  table behaving as specified; 2.1 AC-6 owns tuning it against demo repos.
- Output path defaults to `analysis.json` in the invocation directory, with
  `--out` to override. No artifact fixes the emit location for this story; 3.2
  is where the served sibling URL (AD-12) is decided.
- `--window-anchor` is visible rather than hidden, and its `--help` text names
  it as test-only (AC-6 permits either).
