## Story

As a developer in a repo directory,
I want one command that runs the staged pipeline and emits a valid `analysis.json`,
So that analysis works end-to-end with visible progress.

## Context (binding)

- PRD FR-1 (analysis half), FR-3, FR-4, FR-7, FR-8; AD-3 (config resolution
  lives HERE: defaults < `.gitnebula.yml` < flags; analyzers get plain
  values), AD-4 (you inject `analyzedAt` + `windowAnchor`), AD-7 (failure
  shape `«stage»: «cause» — «remedy»`), AD-10 (llm key notice + `enrich`
  identity hook), AD-13 (anchor), ADR-0002 (scanner exports exclude/layer
  data — you merge user config over it).
- The pipeline: `scan → (deps ∥ githist) → assemble + validate → enrich →
  emit`. Assemble merges results and runs `validateAnalysis`; it does NOT
  aggregate (analyzers did).

## Acceptance Criteria

- AC-1: Config resolver: defaults < `.gitnebula.yml` < CLI flags; supports
  excludes, windowDays, layers, hotspotThreshold, llm (passthrough); invalid
  config fails fast naming key and line; the llm key prints exactly one
  ignored-in-MVP notice (FR-4, AD-10).
- AC-2: Each stage prints a start line and an end line with elapsed time;
  `onProgress` from analyzers renders within-stage counts; a stage failure
  exits non-zero with the AD-7 shape (test: point it at a non-git dir).
- AC-3: Emitted `analysis.json` passes `validateAnalysis`; `analyzedAt` and
  `windowAnchor` are injected here and nowhere else; two runs on the fixture
  repo differ only in `analyzedAt` (byte-compare test with anchor pinned via
  flag).
- AC-4: `enrich(analysis)` identity hook sits between validate and emit;
  with no llm config: no warnings, no output degradation (FR-8).
- AC-5: End-to-end on the built fixture repo with ALL THREE analyzers wired:
  emitted file's snapshot matches committed expectations — this is the M2
  evidence; quote the test's summary line in the PR body.
- AC-6: A `--window-anchor <iso>` (or equivalent hidden flag) exists for
  deterministic testing and is documented as test-only.
