## Story

As a developer exploring the map,
I want zoom to unfold modules, hover to reveal dependency chains, and search to fly me anywhere,
So that a 2,000-file repo is navigable in seconds.

## Context (binding)

- PRD FR-16, FR-17, FR-18; ADR-0006 (viewport-scoped unfold — spawn members
  at module position, settle locally, global layout undisturbed), AD-5
  (everything through the GraphEngine interface from 2.5 — frozen), AD-6
  (determinism holds through unfold), UX-DR5, 8, 10, 11.
- Mockup constants: UNFOLD_ZOOM 1.8, file labels ≥ 3.0×, chain alphas
  0.62/0.03, dim 0.1, flyTo 620 ms cubic ease-out, targetK 2 (module) /
  3 (file).

## Acceptance Criteria

- AC-1: Crossing 1.8× unfolds ONLY modules intersecting the viewport
  (+margin); panning a collapsed module into view at ≥ 1.8× unfolds it;
  dropping below 1.8× collapses all; file labels from 3.0×; member files
  spawn at their module's position and settle locally — automated test
  asserts non-member displacement stays under the Settled bound during an
  unfold (FR-16).
- AC-2: Hover highlights the one-hop chain (chain edges 0.62; a hovered
  module also lights its member files when unfolded); non-chain nodes dim
  to 0.1, edges to 0.03; tooltip `name · churn N%` follows the cursor,
  never overflows the viewport; hover exit restores full opacity (FR-17).
- AC-3: The persistent search box (top-left, `⌘K` kbd hint) focuses via
  Cmd/Ctrl+K and `/`; fuzzy subsequence match over node ids; top 7 results;
  arrows + Enter navigate, Esc closes and blurs; selecting flies the camera
  620 ± 50 ms ease-out to 2.0× (module) / 3.0× (file), pulses the target,
  opens the panel via an engine event (3.4 consumes it); a file inside a
  collapsed module unfolds it on arrival; reduced-motion jumps instantly
  (FR-18, UX-DR8/11).
- AC-4: All interaction flows through the GraphEngine interface + events —
  no new direct canvas access outside the engine (the 2.5 boundary check
  still passes).

### Debug Log References

Two defects were found by driving the built viewer in a real Chrome against the
`synthetic-100x2000` fixture. Neither was visible to the unit suite as first
written; both now carry regression tests that were confirmed red before the fix.

1. **Unfold went stale during a camera flight.** `advanceFlight` assigns
   `this.camera` directly rather than calling `setCamera` — it must, since
   `setCamera` cancels the flight it is animating — so the unfold recompute was
   skipped for every animated frame. Symptom: a fly-to arrived at 3.0× with only
   its target's module unfolded while every visible neighbour stayed collapsed.
   The suite missed it because its flights used `durationMs: 0`, which *does*
   route through `setCamera`. Fix: recompute unfolds inside `advanceFlight`.
   Test: "unfolds the other modules a real flight lands among".

2. **The settle-completion `fit()` cancelled a user's fly-to.** The search box
   is usable from the first frame, but the map settles over 2–3 s; a search
   started in that window had its flight cancelled by the automatic fit, so
   search appeared to do nothing at all. Fix: a pan, zoom or fly-to sets
   `cameraTakenByUser`, which suppresses the settle-completion fit. Test: "keeps
   a fly-to started before the layout settled".

Also measured rather than assumed: spawning members on their module's exact
point put `forceManyBody` at its `distanceMin` floor for every pair at once and
threw the cloud ~150 px outward on the first tick. Replaced with a 12 px
golden-angle spawn disc (`MEMBER_SPAWN_RADIUS`).

A third defect was found by story 3.4's Codex review and taken here rather than
left to that branch (`load()` cleared selection/hover/isolate by direct field
assignment, emitting nothing, which left this story's new chrome subscriptions
holding stale state). Fix and two tests in this branch; 3.4's owner was told to
drop his hunk.

Browser verification cannot check wall-clock timing: an unfocused automation tab
throttles `requestAnimationFrame`, so flights crawl and `await flyTo(...)` never
resolves inside the CDP timeout. Timing is asserted on the deterministic frame
clock in `navigation.test.ts`; `MANUAL_TESTING.md` records what that leaves for
a human.

### Completion Notes List

- All four ACs implemented. `pnpm --filter @gitnebula/viz test` → **242 passing**
  (21 files); `pnpm lint` and `pnpm build` clean.
- **No engine interface change.** Story 2.5 declared the whole `GraphEngine`
  interface up front, including what it did not implement, so this story filled
  in `flyTo`, `unfoldedModules`, `isUnfolded` and the hover path against a shape
  three agents had already frozen. No event added, none reshaped.
- **AC-1 locality is structural, not tuned.** A `MemberLayout` contains only one
  module's files — not the module, not any sibling — so no force in a wake can
  reach a node that must not move. The displacement assertion was verified to go
  red when a non-member is displaced, so it guards rather than restates.
- **AC-4 held without touching the boundary test.** `MemberLayout` went into
  `layout.ts` rather than a new file, because `boundary.test.ts` asserts exactly
  one engine module imports d3-force. `layout.ts`'s own 2.5 header already
  anticipated this code landing there. One fewer file than my intent declared.
- **Determinism through unfold (AD-6).** Each wake is seeded from
  `hash(moduleId) ^ documentSeed`, not from the shared settle stream, so a
  module's cloud does not depend on the order the user panned through the map.
  Asserted by a test that unfolds the same module in two engines.
- **Own fuzzy scorer, no dependency** — the spec's "only if quality demands" was
  not met: the corpus is paths, so the ranking that matters is path-shaped.
  Ties break alphabetically, so the list is a deterministic function of the query.
- Cohort seams negotiated before writing code and honoured: click-to-select left
  to 3.4; `exportPNG`'s stub left byte-identical for 3.5; the `buildScene`
  extraction taken on by this story with an order-independent conflict rule
  agreed with 3.5's owner. Shared chrome files were edited append-only, and
  `mountChrome`'s signature and return type are unchanged.
- `chrome.test.ts`'s hardcoded `expect(offCalls).toBe(2)` became the invariant it
  meant (`offCalls === subscriptions`), so 3.4 and 3.5 adding listeners will not
  trip it.
- One ordering change worth a reviewer's eye: `app.ts` now calls `engine.load()`
  before `connectEngine()`, because the search corpus comes from `engine.nodes`.
  See `DECISIONS.md` D10.
- **Not fixed, reported:** the root `pnpm test` fixture-build race (story 3.6).
  `githist` passes 74/74 in isolation; this story's own command is unaffected.
- Full reasoning for every non-trivial call is in `DECISIONS.md` (D1–D10).
