## Story

As a developer inspecting a node,
I want a detail panel with history metrics and a heatmap mode,
So that hot spots and coupling become explorable evidence.

## Context (binding)

- PRD FR-19, FR-20, FR-21; AD-5 (chrome ↔ engine only via interface),
  AD-10 (inert description slot — rendered nowhere, present in the
  component API), UX-DR7 (panel layout per mockup: name+badge, kind line,
  metric rows, churn bar, isolate + GitHub actions, × close), mockup
  nodeColor heat formula for the heatmap ramp.
- Top-3 co-changing modules: SELECT + SORT from the contract's module-level
  cochange pairs. Computing new aggregations in viz violates AD-1.

## Acceptance Criteria

- AC-1: Clicking a node opens the panel: name, path, `kind · layer`, files
  (modules only, `—` for files), LOC (locale-formatted), churn %, authors,
  relative last-change ("2 days ago"), top-3 co-changing modules with
  counts, hot badge when churn ≥ configured threshold, churn bar width =
  churn %; selection ring (light stroke, radius + 5) on the node while
  open (FR-19).
- AC-2: The panel component accepts an optional `description` value and
  renders NOTHING for it in MVP — no placeholder, no hint (AD-10); a test
  mounts the panel with a description and asserts absence.
- AC-3: "open on github" builds `<remoteUrl>/tree/<defaultBranch>/<path>`
  (blob for files) and is absent entirely for non-GitHub remotes; "isolate"
  dims all non-chain elements at hover-dim levels until toggled off or the
  panel closes (FR-20).
- AC-4: Clicking empty canvas closes the panel and clears selection AND
  isolate; a drag that moved never selects (mousedown/mouseup distance
  discrimination per mockup) (FR-20).
- AC-5: Mode toggle Structure ↔ Heatmap: heatmap colours every node by the
  mockup's cold→hot interpolation over churn; `aria-pressed` reflects
  state; mode survives unfold/collapse and panel interactions; search
  fly-to from 3.3 opens the panel via the engine event (FR-21, FR-18).

### Completion Notes List

- All five ACs implemented and covered by unit tests, then **executed in a
  real browser** against this repository's own `analysis.json` — the committed
  fixtures all carry `remoteUrl: null`, so AC-3's GitHub action cannot appear
  under any of them. Observed results are recorded inline in
  `MANUAL_TESTING.md`.
- Two AC clauses are **not** manually verified and say so in
  `MANUAL_TESTING.md`, because their preconditions are story 3.3's and are not
  on this base: a file node's panel (nothing unfolds yet, so `pick()` can only
  return a module) and search fly-to opening the panel (there is no search).
  Both are unit tested directly — the panel opens from the `select` event
  regardless of what emitted it — and both get re-checked after the 3.3
  rebase.
- **Same-kind co-change partners.** A module names module partners, exactly as
  the spec's context line asks. A file names file partners: rolling a file's
  partners up to module level would be a new aggregation computed in `viz`,
  which AD-1 forbids. The spec's two halves pull against each other here and
  AD-1 breaks the tie.
- **Divergence from the mockup, deliberate, three of them.** (1) The churn row
  is labelled from `repo.analysisWindowDays` rather than the mockup's
  hardcoded `90d` — the synthetic fixture analyses 365 days. (2) A path line
  was added under the heading, because AC-1 asks for name **and** path and a
  file's heading is its basename. (3) `CLICK_SLOP_PX = 4` replaces the
  mockup's any-move flag, which loses a click to a one-pixel tremor.
- **`mountChrome`'s return type widened** from `Store<ChromeState>` to a
  `ChromeHandle` that extends it, and `connectEngine` gained a third parameter
  carrying the document. The panel's controls exist before the engine does —
  the engine measures a stage that must already be in the document — so they
  reach it through `attachEngine`. Every existing caller compiles unchanged.
  This is the one shared-seam signature that moved; flagged in the PR body.
- **Isolate drops when the selection changes**, which the mockup does not do.
  AC-3 says isolate holds until toggled off or the panel closes; leaving the
  map dimmed around a node the panel no longer shows reads as a bug.
- **No new aggregation, no engine reshaping, no contract change.** The heat
  ramp and the selection ring were already in `render.ts` from 2.5; this story
  adds the control that reaches them, not a second copy of either.
- Verification: `pnpm lint` clean, `pnpm --filter @gitnebula/viz test`
  204/204 passing, `pnpm build` green.
