## Story

As a developer inspecting a node,
I want a detail panel with history metrics and a heatmap mode,
So that hot spots and coupling become explorable evidence.

## Context (binding)

- PRD FR-19, FR-20, FR-21; AD-5 (chrome ↔ engine only via interface),
  AD-10 (inert description slot — rendered nowhere, present in the
  component API), UX-DR7 (panel layout per mockup: name+badge, kind line,
  metric rows, churn bar, isolate + GitHub actions, × close), mockup
  nodeColor heat formula for the heatmap ramp.
- Top-3 co-changing modules: SELECT + SORT from the contract's module-level
  cochange pairs. Computing new aggregations in viz violates AD-1.

## Acceptance Criteria

- AC-1: Clicking a node opens the panel: name, path, `kind · layer`, files
  (modules only, `—` for files), LOC (locale-formatted), churn %, authors,
  relative last-change ("2 days ago"), top-3 co-changing modules with
  counts, hot badge when churn ≥ configured threshold, churn bar width =
  churn %; selection ring (light stroke, radius + 5) on the node while
  open (FR-19).
- AC-2: The panel component accepts an optional `description` value and
  renders NOTHING for it in MVP — no placeholder, no hint (AD-10); a test
  mounts the panel with a description and asserts absence.
- AC-3: "open on github" builds `<remoteUrl>/tree/<defaultBranch>/<path>`
  (blob for files) and is absent entirely for non-GitHub remotes; "isolate"
  dims all non-chain elements at hover-dim levels until toggled off or the
  panel closes (FR-20).
- AC-4: Clicking empty canvas closes the panel and clears selection AND
  isolate; a drag that moved never selects (mousedown/mouseup distance
  discrimination per mockup) (FR-20).
- AC-5: Mode toggle Structure ↔ Heatmap: heatmap colours every node by the
  mockup's cold→hot interpolation over churn; `aria-pressed` reflects
  state; mode survives unfold/collapse and panel interactions; search
  fly-to from 3.3 opens the panel via the engine event (FR-21, FR-18).
