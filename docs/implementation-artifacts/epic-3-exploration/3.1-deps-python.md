## Story

As a developer exploring a Python repo,
I want Python imports resolved to repo files via the WASM grammar,
So that mixed and Python repos get real edges with zero native compilation.

## Context (binding)

- PRD FR-11; ADR-0001 (web-tree-sitter WASM — node-gyp anywhere in the npx
  path is a product-requirement violation), AD-11 + Stack (grammar built
  in-repo with pinned tree-sitter-cli, ABI-matched to web-tree-sitter 0.26
  — see tree-sitter#5171; `.wasm` committed as a deps asset; resolved via
  `import.meta.url`), AD-7/AD-13 (counters, universe).

## Acceptance Criteria

- AC-1: `scripts/build-grammar.sh` (or .ts) builds `tree-sitter-python.wasm`
  with the PINNED tree-sitter-cli version; rebuilding reproduces the
  committed artifact byte-identically; the pin and ABI rationale are in the
  script header.
- AC-2: Parser loads the `.wasm` via `import.meta.url` (test proves load
  from package source; 4.1 will prove the bundled path).
- AC-3: Crafted Python fixture resolves: absolute intra-repo imports
  (`import pkg.mod`, `from pkg import mod`), relative (`from . import x`,
  `from ..pkg import y`), packages via `__init__.py`; stdlib and
  site-packages imports are counted `external`, never edges.
- AC-4: Syntax-error file → no edges + one warning; stage completes.
- AC-5: Edges join the same universe-filter/aggregation/sort plumbing as
  TS/JS (one output path, two parsers); snapshots stay byte-identical.
- AC-6: Local run on streamlit (pinned SHA): both languages produce edges;
  combined unresolved rate recorded in docs README, ≤ 20%.
- AC-7: WASM parser init time measured and recorded (feeds the 60 s budget
  accounting; > 2 s init is a finding to flag, not silently accept).

### Debug Log References

- **The `.wasm` is reproducible, but only under a fixed output name.** The first
  two builds differed in exactly one byte, at offset 459412: the emitted module
  records its own output basename, so `-o out1.wasm` and `-o out2.wasm` are not
  the same file. Rebuilt under one name from two different working directories:
  identical, `36d25eee776af6293dc67bdf6f8f820af6a26bbc49e335cc4821dfd5a0dac685`.
  The build script fixes the name and says why in its header.
- **No Docker needed.** `tree-sitter-cli` 0.26.12 builds WASM with a wasi-sdk
  toolchain it downloads to `~/.cache/tree-sitter`; emscripten and Docker are not
  on the path this takes.
- **`from __future__ import annotations` has its own grammar node type**
  (`future_import_statement`) with no `module_name` field, so a query matching
  only `import_statement`/`import_from_statement` silently misses it. Handled
  explicitly and covered by a test.
- **streamlit probe.** Before writing the numbers down, a throwaway probe over
  all 1,171 Python files confirmed where the misses are: zero unresolved
  relative imports on the Python side (all 247 are TS/JS-side, story 2.2's known
  bare-specifier limitation), and the single unparsable file is
  `e2e_playwright/compilation_error_dialog.py`, which streamlit keeps
  deliberately broken.

### Completion Notes List

- All seven acceptance criteria are met. AC-1 through AC-5 and AC-7 are
  executable from `pnpm --filter @gitnebula/deps test`; AC-6 is the opt-in
  local measurement, recorded with its reproduction command in the docs README.
- **AC-1 — the reproducibility test is opt-in.** A real rebuild downloads the
  pinned CLI plus a 106 MB toolchain and takes minutes; the default suite is
  offline by construction (AD-8). `scripts/build-grammar.sh --check` does the
  byte comparison and a test runs it behind `GITNEBULA_BUILD_GRAMMAR=1`; the
  default suite asserts the committed artifact's `.sha256` and the pins in the
  script. Deviation from a literal reading of AC-1, stated here deliberately.
- **AC-6 — streamlit at `753fc013bb2a2781b1ff4830cc2b792103f2b9df`:** 6,845 file
  edges (3,958 Python, 2,887 TS/JS), 247 unresolved = **3.5%** over resolvable
  specifiers, against a 20% threshold. Both languages produce edges.
- **AC-7 — WASM init is 7.2 ms** (6.5 ms on a second cold run), against the
  spec's 2 s flag line. Nothing to flag. Recorded in `PERFORMANCE.md` with the
  method; the test asserts the budget so a regression fails rather than slows.
- **AC-5 holds structurally, not just observably:** `edges.ts` and `warnings.ts`
  are untouched, and story 2.2's snapshot is byte-identical.
- One behaviour change outside the new code: `onProgress` now counts both
  languages on one scale (a Python repo previously reported `0/0`). The
  callback's shape is unchanged, so cli needs no change.
- Judgement calls, with sources and confidence, are in `DECISIONS.md` — the ones
  a reviewer should look at first are D2 (opt-in rebuild), D4 (`.pyi` stubs are
  not parsed), D6 (source-root detection) and D7 (absolute miss = external).
- Manual testing: not applicable and no `MANUAL_TESTING.md`. The story ships a
  library function inside the Node pipeline — no UI, no route, no keyboard
  surface.
