# Story 3.2: Serve and URL mode

> **Status: ready-for-dev** · Owner: `cli` · Touches: — · Depends_on: `[]`
>
> No dependencies — start immediately. The pipeline (2.4) is on master; you
> add the server and the URL entry around it.

## Story

As a developer,
I want the CLI to serve the map locally and accept a GitHub URL,
So that `npx gitnebula` ends in an open browser, and remote repos are one command away.

## Context (binding)

- PRD FR-2, FR-5; AD-8 (127.0.0.1 ONLY; clone is the single sanctioned
  network op), AD-12 (`analysis.json` at the sibling URL next to the viz
  dist), Stack (node:http — no server framework; `open` for the browser).
- In dev, the viz dist may not exist — serve `packages/viz/dist` when built,
  else print the AD-7-shaped hint to run the viz build. Do not reach into
  viz sources.

## Acceptance Criteria

- AC-1: Server binds `127.0.0.1` exclusively (test asserts the bound
  address; `0.0.0.0` never appears in the code path); default port with
  auto-increment scan when taken; chosen URL printed; browser opened via
  `open` (suppressible with `--no-open` for CI).
- AC-2: Serves the viz dist and the generated `analysis.json` at the
  same-directory sibling URL (AD-12); correct content-types; no directory
  listing; unknown paths → 404 (no fallthrough file reads outside the dist).
- AC-3: Ctrl+C shuts down cleanly (socket closed, exit 0; test via signal).
- AC-4: `gitnebula <github-url>`: shallow clone (`--shallow-since` = window
  start, full-clone fallback on server refusal) into a temp dir; analysis
  runs identically; temp dir removed on exit — success AND failure paths
  tested; no network use after the clone.
- AC-5: A non-existent URL / network failure aborts with the AD-7 shape
  (`clone: … — check the URL or your network`), non-zero exit, temp cleaned.
