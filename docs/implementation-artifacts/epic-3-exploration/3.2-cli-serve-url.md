# Story 3.2: Serve and URL mode

> **Status: ready-for-dev** · Owner: `cli` · Touches: — · Depends_on: `[]`
>
> No dependencies — start immediately. The pipeline (2.4) is on master; you
> add the server and the URL entry around it.

## Story

As a developer,
I want the CLI to serve the map locally and accept a GitHub URL,
So that `npx gitnebula` ends in an open browser, and remote repos are one command away.

## Context (binding)

- PRD FR-2, FR-5; AD-8 (127.0.0.1 ONLY; clone is the single sanctioned
  network op), AD-12 (`analysis.json` at the sibling URL next to the viz
  dist), Stack (node:http — no server framework; `open` for the browser).
- In dev, the viz dist may not exist — serve `packages/viz/dist` when built,
  else print the AD-7-shaped hint to run the viz build. Do not reach into
  viz sources.

## Acceptance Criteria

- AC-1: Server binds `127.0.0.1` exclusively (test asserts the bound
  address; `0.0.0.0` never appears in the code path); default port with
  auto-increment scan when taken; chosen URL printed; browser opened via
  `open` (suppressible with `--no-open` for CI).
- AC-2: Serves the viz dist and the generated `analysis.json` at the
  same-directory sibling URL (AD-12); correct content-types; no directory
  listing; unknown paths → 404 (no fallthrough file reads outside the dist).
- AC-3: Ctrl+C shuts down cleanly (socket closed, exit 0; test via signal).
- AC-4: `gitnebula <github-url>`: shallow clone (`--shallow-since` = window
  start, full-clone fallback on server refusal) into a temp dir; analysis
  runs identically; temp dir removed on exit — success AND failure paths
  tested; no network use after the clone.
- AC-5: A non-existent URL / network failure aborts with the AD-7 shape
  (`clone: … — check the URL or your network`), non-zero exit, temp cleaned.

- Similarly, the first shallow-clone assertion (`--is-shallow-repository`) was

### Completion Notes List

- All five ACs implemented and covered; `pnpm --filter @gitnebula/cli test`
  passes with 113 tests, `pnpm lint` and `pnpm build` exit 0.
- **`--no-serve` added beyond the spec's `--no-open`.** Serving is now the
  default tail of every run, and `--no-open` suppresses only the browser — so
  without `--no-serve` there would be no non-interactive way to run the
  analysis, and the package's existing tests would block forever. Rationale in
  `DECISIONS.md` §1.
- Default port is **4137**, scanning 20 upward. The spec and FR-5 require the
  scan but name no default; 4137 misses 3000/4173/5173/8080 and macOS's
  reserved 5000/7000. `DECISIONS.md` §2.
- `--shallow-since` uses `--window-days` or the 90-day default, never
  `.gitnebula.yml`: that file lives inside the repository that does not exist
  yet. `DECISIONS.md` §3.
- The full-clone fallback triggers on *any* shallow failure rather than on a
  parsed "server refuses" message. This was exercised for real in manual
  testing: `octocat/Hello-World` has only 2011 commits, so the shallow request
  selects none, git refuses, and the fallback carried the run. `DECISIONS.md` §6.
- AC-3's signal test drives an injected emitter — vitest runs the TS sources
  directly (AD-11), so there is no artifact to spawn and signal. The real
  `kill -INT` against `dist/gitnebula.js` was run manually and is recorded in
  `MANUAL_TESTING.md` §4 (exit code 0, port released). `DECISIONS.md` §4.
- `MANUAL_TESTING.md`: 6 of 7 sections executed against the built binary,
  including a real GitHub clone and a real bad-URL abort. Section 7 (does the
  nebula look right in a browser; does `open` reach a real desktop) is left
  unticked with the reason stated — it needs a human at a GUI.
- New runtime dependency: `open` ^11 in `@gitnebula/cli`, as the Stack brief
  specifies.
- No contract change; no viz dependency introduced (the dist is located by
  path, never imported).
