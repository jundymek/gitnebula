## Scheduling note for the maintainer

The requirement that this story merge before `4.2-ci-pages-recipe` cannot be
expressed from inside this file: the scheduler reads each story's own
`Depends_on`, and 4.2 lists only `4.1-build-bundle`. Adding `3.6` to 4.2's
metadata means editing a story spec that already exists, which the
supervisor who wrote this file is not permitted to do — so it is recorded
here as an escalation rather than silently left as prose that nothing
enforces. **If 4.2 is launched without this story merged, CI comes up
running a command that fails roughly half the time.**

## Context (binding)

`test-fixtures/build-fixture-repo.sh` begins with `rm -rf "$REPO_DIR"` on a
shared directory, and **four callers invoke it**:

| caller | line |
| --- | --- |
| root `pretest` | `package.json:14` |
| contract's fixture test | `packages/contract/src/fixture-repo.test.ts:9` |
| githist's suite | `packages/githist/src/index.test.ts:15` |
| scanner's fixture test | `packages/scanner/src/fixture-repo.test.ts:21` |

`pnpm -r test` runs packages **in parallel**, so one package deletes the
fixture repository while another is reading it. The script is idempotent
when run alone — the `rm -rf` is deliberate and correct for a single caller
— and every package passes in isolation. Serially the workspace is fully
green at 496 tests: contract 103, scanner 145, deps 24 (1 skipped),
githist 74, viz 148, cli 2.

What this costs today:

- **`pnpm lint && pnpm test`, which this project's stack brief names as the
  minimum before any commit, fails roughly half the time** on the epic head.
- Story **4.2 turns `.github/workflows/ci.yml` on**, and CI runs exactly the
  failing command. Left alone, this arrives as an intermittent CI failure
  that looks like a flaky analyzer rather than a build-order defect.
- No per-story gate was wrongly passed: every story's own test command
  (`pnpm --filter @gitnebula/<pkg> test`) is unaffected, then and now.

`packages/cli` briefly became a fifth participant during 2.4 and its author
already made its `pretest` conditional. That is a workaround for one
package, not the fix, and this story supersedes it.

Constraints that still bind you:

- **AD-14** — fixtures are built, never committed.
- **AD-4 / determinism** — the built repository's commit hashes are pinned by
  the snapshots in stories 2.1, 2.3 and 2.4. **The hashes must not move.**
  Changing the script's crafted history is out of scope and would silently
  invalidate three merged snapshots.
- `test-fixtures/build-ts-fixture-repo.sh` (deps, story 2.2) writes a
  different tree and has a single caller. Bring it into whatever discipline
  you choose only if that costs nothing; it is not the defect.

## Acceptance Criteria

- AC-1: `pnpm test` from the workspace root passes **10 consecutive times**
  from a clean checkout with no `.generated/` present. Record the run in the
  docs README.
- AC-2: The fixture repository is never built by two callers at once, AND a
  package run on its own still gets one. Those two halves are the whole
  problem: `packages/contract`, `packages/scanner` and `packages/githist`
  have no `pretest` of their own, so their in-test rebuild is the only thing
  that gives them a fixture when run standalone — deleting it in favour of a
  root-only build would satisfy this criterion and break AC-3. Any mechanism
  that holds both is acceptable (a lock; building into a temp directory and
  renaming atomically; a build that no-ops when a valid repository is
  already present; a per-package `pretest` that is safe to run concurrently).
  State which you chose in the story README, and say what you rejected and
  why.
- AC-3: Every package's own test command still works from a clean state with
  no prior root `pretest` — `pnpm --filter @gitnebula/<pkg> test` for each of
  contract, scanner, githist, deps, cli, viz. A fix that only works via the
  root command breaks every story agent's inner loop.
- AC-4: The commit hashes of the built fixture repository are **unchanged**.
  Prove it: capture `git -C test-fixtures/.generated/history-repo log
  --format=%H` before and after your change and show they are identical.
  The snapshots committed by 2.1, 2.3 and 2.4 must pass untouched.
- AC-5: A test or CI-visible guard fails if a fifth concurrent caller is
  reintroduced later — this defect was added incrementally by three separate
  stories, each reasonably, and nothing stopped them.
- AC-6: `packages/cli` carries no `pretest` that rebuilds the fixture
  repository. Story 2.4 added a conditional one as a local workaround; if it
  is still present, remove it, since the underlying defect is gone. If a
  later story removed it first, assert its absence and say so in the story
  README — this criterion is about the end state, not about performing a
  deletion.
