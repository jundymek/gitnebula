## Story

As an OSS maintainer,
I want a ready-made Actions workflow regenerating the map on push,
So that my README's map is always current — proven on gitnebula itself.

## Context (binding)

- PRD FR-24, SM-5; ADR-0004 (sibling analysis.json → data refresh without
  app rebuild — the recipe should exploit it), AD-8 (the workflow must not
  introduce external requests into the bundle).
- Two deliverables: (a) a copy-paste recipe in docs for ANY user's repo,
  (b) that recipe applied to THIS repo, publishing to GitHub Pages.

## Acceptance Criteria

- AC-1: `docs/publishing.md` (or equivalent) contains the complete workflow
  YAML: checkout with history depth covering the window, run analysis +
  `gitnebula build`, deploy to Pages via the official actions; prose covers
  the one-time Pages setup and the data-only refresh property.
- AC-2: The workflow, added to this repository, runs green on push to
  master and publishes the live map of gitnebula (Pages URL recorded in
  the docs and handed to 4.3 for the README).
- AC-3: The workflow pins action versions and completes in reasonable time
  (recorded; > 5 min is a finding).
- AC-4: The published map is validated by a post-deploy smoke check (fetch
  the Pages URL, assert 200 + `analysis.json` present) — in the workflow
  itself.
- AC-5: Owner gate: enabling Pages on the repository is a maintainer click —
  task is listed and **MUST be left unticked** for the owner; everything
  else automated.
