## Provenance

Found by the supervisor's closure review of Epic 4 on 2026-08-13, after all
three story PRs had merged. Neither story is at fault; **the merge produced
it**, which is why no per-PR review could have caught it:

- Story 4.1 (PR #37) moved the built binary from `dist/gitnebula.js` to
  `dist/bin/gitnebula.js`. Deliberately — its `tsup.config.ts` explains that
  `@gitnebula/deps` resolves the grammar as `../../assets/…` from its own
  module, so a binary emitted at `dist/` resolves outside the package and the
  binary dies on the first Python file it meets.
- Story 4.3 (PR #36) wrote the README, CONTRIBUTING and the recording recipe
  against the path that existed when it was written, and merged first.

Verified on the epic head after both merged: `pnpm build` produces
`packages/cli/dist/bin/gitnebula.js`, and `packages/cli/dist/gitnebula.js`
does not exist. The three references are:

| file | line | what it claims |
| ---- | ---- | -------------- |
| `README.md` | 54 | the pre-release fallback — **the one command a visitor can actually run today**, because `npx gitnebula` is not published until 4.5 |
| `CONTRIBUTING.md` | 36 | "run the tool on this repo" |
| `docs/recording-demo.md` | 56 | the demo re-recording recipe |

A second, smaller drift from the same merge: **the README never mentions
`gitnebula build`** (FR-23), the command 4.1 shipped. Story 4.3's PR body
flagged it as a follow-up for whoever merged 4.1 — "the README needs a `build`
line in the quickstart and the real Pages URL" — and no story owned it.

## Story

As a visitor who just cloned the repository,
I want the commands in the README to run,
So that my first contact with the tool is not an `ENOENT`.

## Context (binding)

- FR-25 and brief §2: the README is a product requirement, not decoration.
- FR-23: `gitnebula build` is a user-facing command and belongs in the
  quickstart.
- The Pages URL stays a placeholder with its `TODO(4.2-ci-pages-recipe)` —
  4.2 is deferred (Actions billing) and this story does not touch it.
- Do **not** "fix" the path by moving the binary back. 4.1's placement is
  load-bearing and its reasoning is in `packages/cli/tsup.config.ts`.

## Acceptance Criteria

- AC-1: `README.md`, `CONTRIBUTING.md` and `docs/recording-demo.md` name
  `packages/cli/dist/bin/gitnebula.js`, and each command they print was run
  from a clean clone as written and observed to work. Where a command cannot
  work as written — a Python repository through a dev checkout, until 4.5's
  AC-6 lands — the text says so instead of implying otherwise.
- AC-2: The README quickstart gains `gitnebula build`: what it writes
  (`index.html` + `analysis.json`, nothing else), the `-o` flag, and one line
  on hosting the result statically. Grounded in what 4.1 shipped — no claim
  about Pages, which is 4.2's.
- AC-3: An automated check fails when an **instructional** document names a
  path under `packages/*/dist/` that does not exist after `pnpm build`. It
  must be watched failing against the pre-fix tree, and it belongs beside the
  existing suites (`pnpm test`), not in a manual step.

  Scope it to documents that tell a reader to run something — `README.md`,
  `CONTRIBUTING.md` and `docs/*.md` — and exclude the record-keeping trees,
  `docs/implementation-artifacts/` and `docs/dev/`, where a dead path is
  often the subject rather than an instruction. This spec is itself an
  example: it names `packages/cli/dist/gitnebula.js` above precisely because
  that file does not exist, and so do the Epic 4 retrospective, 4.1's story
  record and `docs/dod-report.md`. A check that cannot tell those apart fails
  forever and gets deleted by whoever next hits it, which is worse than no
  check. If a genuine instruction ever needs a dead path, an explicit inline
  exemption marker is the way — never widening the exclusion to a whole file.
- AC-4: `pnpm lint`, `pnpm typecheck` and `pnpm test` exit 0, and the story's
  own check is part of that run.

### Completion Notes List

- The three paths now name `packages/cli/dist/bin/gitnebula.js`, and every
  command the three documents print was executed from a fresh clone (17 of 21
  steps; the four unexecuted ones are `npx gitnebula`, unpublished until 4.5,
  the browser rendering of a hosted bundle, and the two demo-recording steps
  that would overwrite a committed asset — each with its reason recorded).
- **Deviation worth reviewing (AC-1).** The clean-clone walk showed the drift
  was not only the rename: after `pnpm install && pnpm build`, serving,
  `gitnebula build` and any Python repository all failed, because
  `packages/cli/assets/` is populated by `packages/cli/scripts/prepack.mjs`,
  which npm runs only on `pack`/`publish` (story 4.5's AC-6). AC-1 allows the
  text to "say so instead", but running that script by hand fixes all three, so
  the three documents print the working recipe including that line with the
  reason beside it — printing a command that works beats printing one that
  fails. No packaging was changed: `pnpm build` remains the only build entry
  and `pack.test.ts` passes untouched. When 4.5's AC-6 lands, each of the three
  documents loses one line.
- README gained a `gitnebula build` section: the two files it writes, `-o`, and
  hosting the result on any static server — with the caveat that the viewer
  fetches its sibling `analysis.json`, so `file://` does not work. No Pages
  claim; 4.2's `TODO(4.2-ci-pages-recipe)` marker is untouched.
- The check is `packages/cli/src/docs-paths.test.ts`, in `pnpm test`. It builds
  the workspace first — a stale `dist/` from before 4.1's rename would still
  hold the dead path and the check would pass on the defect it exists to catch.
  Because `pack.test.ts` already built unconditionally and vitest runs files in
  parallel workers, `build()` moved into `test-support.ts` as
  `buildWorkspace()` behind a directory lock and a completion stamp, so the two
  suites cannot race on a `clean: true` output directory. `pack.test.ts`'s
  semantics are unchanged.
- Scope of the scan is AC-3's: `README.md`, `CONTRIBUTING.md`, `docs/*.md`;
  `docs/implementation-artifacts/` and `docs/dev/` excluded; inline
  `<!-- stale-path-ok: <path> — reason -->` as the per-path escape hatch. No
  exemption was needed on this tree. `docs/dod-report.md` is in scope and
  passes — its reference is the directory `packages/cli/dist/`.
- `pnpm lint`, `pnpm typecheck` and `pnpm test` all exit 0; `packages/cli` is
  14 files / 141 tests.
