> No dependencies — start immediately. Story 4.2 waits on YOUR `done`.

## Story

As an OSS maintainer,
I want `gitnebula build` to emit a static, self-contained bundle — and the npm
package to actually work cold,
So that my repo's map hosts on GitHub Pages and `npx gitnebula` is real.

## Context (binding)

- PRD FR-23; ADR-0004 (bundle shape: one self-contained index.html, system
  fonts, sibling analysis.json, ≤ 2 MB gz, `file://` unsupported →
  clear error), AD-11 (tsup inline of workspace deps; prepack copies viz
  dist + `.wasm` into cli assets; only `gitnebula` published; semver ⊥
  schemaVersion), AD-12 (sibling URL), AD-8 (zero external requests).

## Acceptance Criteria

- AC-1: `gitnebula build [-o dir]` writes exactly: `index.html` (inlined
  JS/CSS, single file, system font stack) + `analysis.json`; nothing else.
  Vite single-file configuration lives in `packages/viz`; the command
  orchestrates analysis (or reuses a fresh `analysis.json`) + copy.
- AC-2: Viewer assets ≤ 2 MB gzipped — CI-checked with the number printed.
- AC-3: Served by any static server, the bundle works fully; an automated
  check (Playwright reuse) asserts the page issues requests ONLY to its own
  two files; opening via `file://` shows the documented error hint.
- AC-4: `npm pack` in CI: the tarball contains the tsup-bundled cli, the viz
  dist, and `tree-sitter-python.wasm`; a test installs the tarball into a
  temp dir (no pnpm, no workspace) and runs the binary against the fixture
  repo to a served map (`--no-open`) — the cold-start proof of AD-11.
- AC-5: `pnpm build` remains the only build entry; internal packages still
  have no build step (AD-11 discipline intact).
