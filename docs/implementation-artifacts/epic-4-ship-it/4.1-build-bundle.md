# Story 4.1: Static bundle and the publishable package

> **Status: ready-for-dev** · Owner: `cli` · Touches: `packages/viz` (build
> config only) · Depends_on: `[]`
>
> No dependencies — start immediately. Story 4.2 waits on YOUR `done`.

## Story

As an OSS maintainer,
I want `gitnebula build` to emit a static, self-contained bundle — and the npm
package to actually work cold,
So that my repo's map hosts on GitHub Pages and `npx gitnebula` is real.

## Context (binding)

- PRD FR-23; ADR-0004 (bundle shape: one self-contained index.html, system
  fonts, sibling analysis.json, ≤ 2 MB gz, `file://` unsupported →
  clear error), AD-11 (tsup inline of workspace deps; prepack copies viz
  dist + `.wasm` into cli assets; only `gitnebula` published; semver ⊥
  schemaVersion), AD-12 (sibling URL), AD-8 (zero external requests).

## Acceptance Criteria

- AC-1: `gitnebula build [-o dir]` writes exactly: `index.html` (inlined
  JS/CSS, single file, system font stack) + `analysis.json`; nothing else.
  Vite single-file configuration lives in `packages/viz`; the command
  orchestrates analysis (or reuses a fresh `analysis.json`) + copy.
- AC-2: Viewer assets ≤ 2 MB gzipped — CI-checked with the number printed.
- AC-3: Served by any static server, the bundle works fully; an automated
  check (Playwright reuse) asserts the page issues requests ONLY to its own
  two files; opening via `file://` shows the documented error hint.
- AC-4: `npm pack` in CI: the tarball contains the tsup-bundled cli, the viz
  dist, and `tree-sitter-python.wasm`; a test installs the tarball into a
  temp dir (no pnpm, no workspace) and runs the binary against the fixture
  repo to a served map (`--no-open`) — the cold-start proof of AD-11.
- AC-5: `pnpm build` remains the only build entry; internal packages still
  have no build step (AD-11 discipline intact).

### Debug Log References

Five defects, each found by running the artefact rather than by reading it.
Full write-up in `docs/dev/epic-4/4.1-build-bundle/README.md`.

1. `deps: Aborted(Error: ENOENT ... packages/cli/dist/web-tree-sitter.wasm)` —
   the built binary aborted on any repository containing Python.
   `web-tree-sitter`'s emscripten glue loads its runtime `.wasm` from beside
   the importing module, which tsup relocated. Fixed by making the package
   external, as `typescript` already is.
2. The grammar `.wasm` resolved to `packages/assets/…`, outside the cli
   package, because `@gitnebula/deps` locates it two directories up from its
   own module and the bundle sat only one directory deep. Fixed by emitting at
   `dist/bin/gitnebula.js`.
3. `npm error code EUNSUPPORTEDPROTOCOL — Unsupported URL Type "catalog:"`, and
   the same for `workspace:`. `pnpm pack` rewrites both protocols and `npm
   pack` does not, so the tarball installed only when packed by the right tool.
4. The single-file inliner spliced a duplicate copy of the page into the
   bundle: `String.replace` re-reads `$'` out of the replacement text, and
   minified JS contains that sequence. Caught by the Playwright network check,
   not by reading the output — the corrupted page still rendered.
5. `gitnebula build -o site` wrote to `./gitnebula-bundle`. The parent command
   also declares `-o`, and commander gives a shared short flag to the parent.
   Fixed with `enablePositionalOptions()`; caught by a test asserting where the
   files actually landed.
6. From the Codex review, and the worst of the set because it produced a
   plausible wrong answer rather than a crash: the reuse rule keyed only on
   mtime versus HEAD, so `build -o site repo-a` followed by
   `build -o site repo-b` published repo-a's map under repo-b's name, and a
   changed `--window-days` or exclusion was ignored just as quietly. Reuse now
   checks provenance and re-analyzes whenever any part of it is unverifiable.

### Completion Notes List

- All five ACs are met. Test command result:
  `pnpm --filter @gitnebula/cli test` → **13 files, 143 tests passed**,
  printing `viewer assets: 57.6 KB gzipped of 2.00 MB budget (2.8%)`.
  The pack e2e's summary line: `cold install: npm-installed tarball analyzed
  the fixture repo and served index.html + analysis.json`.
- AC-3's browser half is `pnpm --filter @gitnebula/viz bundle-check` (4 passed):
  the built bundle served by a plain `node:http` host, asserting the request
  pathnames are exactly `["/", "/analysis.json"]`, that the page carries no
  `script[src]` or stylesheet link, and that a `file://` open shows the
  documented hint with zero failed requests.
- **Divergence from the spec's Touches line**, flagged rather than hidden: AC-3
  requires a `file://` error hint, which is browser-side behaviour and can only
  live in `packages/viz/src/loader.ts`. The header scopes viz to "build config
  only". The AC wins; the change is 20 lines and one exported constant.
- **Divergence from AD-11**, flagged: AD-11 names `gitnebula` as the published
  artefact. The package keeps the name `@gitnebula/cli` — this story's own test
  command names it that way, as does every other spec, doc and CI step, and the
  package is still `"private": true`. The rename is a publish-time act for the
  maintainer; the tarball's *contents*, which is what AC-4 asks about, are
  proven by the cold-start test.
- `@gitnebula/*` moved from `dependencies` to `devDependencies` in
  `packages/cli/package.json`. AD-2's edge is still declared and still enforced
  by lint and tsconfig; the move is what makes `npm install <tarball>` possible
  at all, and it is honest — tsup inlines those packages, so nothing resolves
  them at runtime. Recorded in `DECISIONS.md`.
- `typescript` in cli's `dependencies` moved off `catalog:` to `^5.9.3` for the
  same reason. The catalog's own comment calls itself "shared dev-dependency
  versions", and this is a runtime dependency.
- AC-2 and AC-3's "CI-checked" is wired into `ci.yml` as a new `bundle` job.
  This repository's CI remains `workflow_dispatch`-only, deliberately, until
  story 4.2 revisits the recipe — turning triggers on here would take 4.2's
  decision. The size gate therefore also runs inside the cli test suite, so it
  cannot rot while CI is off.
- `pack.test.ts` is the only test in the workspace that reaches the network:
  `npm install <tarball>` resolves the four runtime dependencies from the
  registry. The product is offline; a test of how the product is *delivered*
  cannot be.
- Two MANUAL_TESTING steps are left unticked with reasons: interaction feel and
  aesthetic comparison against `reference/mockup.html` both need a human eye.
  Every other step was executed and its observed result recorded inline.
