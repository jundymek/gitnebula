## Acceptance Criteria

- AC-1: A committed `docs/dod-report.md` records, per demo repo (pinned
  SHA, reference hardware spec): wall-clock `npx gitnebula` time (≤ 60 s),
  crash-free completion, `analysis.json` size (≤ 5 MB), unresolved-import
  rate (≤ 20%), schema validation pass.
- AC-2: The report records the global checks: offline run (network
  disabled) on a local path; bundle zero-external-requests re-check;
  fps harness number on reference hardware; viewer bundle gzip size.
- AC-3: Every failed threshold gets a filed GitHub issue linked from the
  report — the report may not hide red numbers (a red number with an issue
  is a valid story outcome; a hidden one is not).
- AC-4: The human-review checklist is prepared for the maintainer: per-repo
  PNG exports embedded/linked, the checklist copied into the report with
  evidence links prefilled — **the checklist walk itself MUST be left
  unticked** (owner gate; superman reports readiness, the owner signs).
- AC-5: `sprint-status.yaml` rows for Epic 4 flipped by their owners; the
  report ends with the M3 go/no-go summary for the epic→master merge.

### Debug Log References

- The built CLI could not run against a demo repo on this base: `dist` resolves
  the tree-sitter grammar at `packages/assets/tree-sitter-python.wasm` and
  nothing puts it there yet — that is exactly the prepack step story 4.1's
  AD-11 task adds. The measured runs used a local, uncommitted copy of the two
  `.wasm` files at that path; the copy was removed before committing (it also
  breaks `fixture-build.test.ts`, which walks every directory under `packages/`
  expecting a manifest).
- The network sandbox was verified in both directions before any offline claim
  was made: inside `sandbox-exec … (deny network*)`, `curl https://github.com`
  fails with `Could not resolve host` (exit 6) and `git ls-remote` cannot reach
  GitHub; outside it both succeed.
- PNG exports were produced through the Viewer's own `exportPNG` via a
  throwaway Playwright spec. It was deleted rather than committed (it would
  fail everyone's `pnpm --filter viz perf` run without its env var) and is
  reproduced verbatim in the story README so the images can be regenerated.
