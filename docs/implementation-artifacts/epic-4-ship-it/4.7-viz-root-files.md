# Story 4.7: The Viewer never draws a repository's root files

## Provenance

Found by the maintainer on 2026-08-13, running the built CLI against
`https://github.com/jundymek/free-proxy` during the Epic 4 manual walk: the map
showed two modules, `.github/` and `fp/`, and nothing else — no `setup.py`, no
`test_proxy.py`, no `README.md`.

The measurement, taken from the emitted documents rather than from the screen:

| repository | file nodes | never drawn | their LOC |
| ---------- | ---------- | ----------- | --------- |
| `free-proxy` | 12 | **7** | **554 of 679 — 82%** |
| `gitnebula` itself | 343 | 12 | 8 231 of 86 901 — 9.5% |

`free-proxy` loses the largest file in the repository (`test_proxy.py`, 172
lines) and its packaging entry point; gitnebula loses `README.md`, `CLAUDE.md`,
`CONTRIBUTING.md` and `eslint.config.js`.

**Neither half of the pipeline is wrong on its own.** Story 2.1 decided, and
recorded in its Dev Agent Record, that *"repository-root files carry
`parent: null` rather than joining a synthetic root module"* — a deliberate
choice, and the right one: a synthetic `./` module would have to claim a layer
by ADR-0002's dominance rule over an arbitrary bag (a test file, a setup
script, a licence), and would report LOC and churn aggregates for files that
share nothing but a directory that is not a grouping. The emitted document is
correct.

The Viewer simply never learned the case. `packages/viz/src/engine/graph.ts:82`
reads:

```ts
if (node.kind !== "file" || node.parent === null) return;
```

so a parent-less file is a member of no module and enters no scene, at any zoom
level. The comment beside it says as much — *"an orphan is simply not a member
of anything"* — written as a defensive note about a contract violation, not as
a description of the ordinary output of every real repository.

**Why no test caught it:** not one contract fixture contains a `kind: "file"`
node with `parent: null`. All six were checked — `single-module`,
`cyclic-imports`, `module-zero-files`, `zero-history`, `empty-graph`,
`synthetic-100x2000` — and every file node in every one of them has a parent.
`viz` is built against the fixtures by design (that is what makes parallel work
possible), so the frontend was developed against a world in which this node
shape does not occur, while the pipeline produces it for every repository that
has a README.

## Story

As someone pointing gitnebula at a repository,
I want the files in its root on the map,
So that the map is the repository rather than a subset of it.

## Context (binding)

- **Do not change the contract, and do not change the scanner.** 2.1's
  `parent: null` decision stands; `analysis.json` is already correct. A
  synthetic root module would be a contract change — its own story, its own
  schema decision, an ADR if structural (`CLAUDE.md`) — and it would invent a
  module the repository does not have.
- ADR-0006 (viewport-scoped semantic unfold) governs what is visible at which
  zoom. A root file has no module to unfold out of, so its visibility rule is
  a decision this story must make and state, not inherit.
- ADR-0002's layer colours apply to a root file exactly as to any other file;
  it already carries its own `layer`.
- The 60 fps budget at 100 modules / 2,000 files (FR-14) is unaffected in
  practice — root files are few — but the story must not regress it.

## Acceptance Criteria

- AC-1: A `kind: "file"` node with `parent: null` is drawn, sized and coloured
  by the same rules as any other file node, and is reachable by hover, search
  and the detail panel like any other node.
- AC-2: Its visibility rule across zoom levels is implemented **and written
  down** in the story's docs: whether a root file is always visible (like a
  module) or appears with unfolding (like a file), and why. Whichever is
  chosen, the global layout must not visibly shift when it appears or
  disappears — the same property `navigation.test.ts` already asserts for
  unfold, held to the same numeric bound.
- AC-3: Dependency edges that touch a root file render correctly in both
  directions — a root file importing into a module and a module importing a
  root file. `free-proxy` is the natural case: `setup.py` and `test_proxy.py`
  sit at the root and reference `fp/`.
- AC-4: A new contract fixture carries at least one root file node — a `file`
  with `parent: null`, with edges — and it is listed in
  `packages/contract/fixtures/README.md` with the edge it exists to exercise.
  This is the gap that hid the defect, so closing it is part of the fix.
- AC-5: A test that fails against today's `graph.ts` and passes after, watched
  failing before it is relied on. `pnpm lint`, `pnpm typecheck` and
  `pnpm test` exit 0.
- AC-6: Measured against the 2,000-node fixture, the frame rate stays within
  story 3.5's recorded floor — recorded in `PERFORMANCE.md` beside the story's
  README with the method and the number, per this project's rules.

### Completion Notes List

- **AC-2 decision: a root file is a top-level node, always visible.** It joins
  the module-level layout beside the modules and never unfolds or collapses.
  `MemberLayout` is anchored on a module and holds that module's members alone
  — the structure that makes ADR-0006's "unfolding does not disturb the global
  layout" true by construction — so a parent-less file has neither an anchor
  nor a membership set and unfold has nothing to express about it. ADR-0006's
  budget bounds the *simulated file count* by viewport; root files number in
  the single digits per repository, so admitting them permanently is a fixed,
  tiny cost. The no-shift half of AC-2 then holds structurally: there is no
  appearance event at all. Asserted anyway, over a full unfold→collapse cycle,
  against `SETTLE_DISPLACEMENT_PX` — the same bound `navigation.test.ts` holds
  the global layout to. Rationale also in
  `docs/dev/epic-4/4.7-viz-root-files/README.md` and in `DECISIONS.md`.
- **Judgement call beyond the letter of the spec**: `topLevelLinks()` in
  `layout.ts` lifts each file edge that touches a root file to the top level
  (`setup.py → fp/proxy.py` becomes `setup.py → fp/`), so a root file settles
  beside the module it imports rather than drifting as a free particle with
  only charge and gravity acting on it. Edges between two modules' files are
  deliberately NOT lifted — the pipeline already aggregated them into a
  module-level edge, and lifting them again would double their pull and change
  the settled layout of every existing document.
- **No contract change and no scanner change**, per the spec's binding Context.
  Story 2.1's `parent: null` stands.
- **Divergence from the spec, flagged**: the spec records this repository
  losing 12 files / 8,231 LOC (9.5%). The branch measures 15 files / 627 LOC of
  79.5k. The file list is a superset of the four the spec names, so the defect
  and the fix are unchanged; the LOC figure most likely counted a lockfile that
  current exclusions drop. Recorded in `MANUAL_TESTING.md` so nobody re-derives
  8,231 and reads the difference as a regression.
- **Verification**: `pnpm lint`, `pnpm typecheck`, `pnpm test` and `pnpm build`
  all exit 0. `pnpm --filter @gitnebula/viz test` — 32 files / 383 tests passed.
  Full suite — 914 passed, 2 skipped, 0 failed (re-run after rebasing onto PR #44).
- **MANUAL_TESTING.md was executed**, 15 of 17 steps. The two left unchecked
  are a screen-reader pass and a subjective look-and-feel judgement, both of
  which need a human at a real display; the reason is stated beside each.
