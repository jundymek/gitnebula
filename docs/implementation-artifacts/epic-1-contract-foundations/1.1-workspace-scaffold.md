## Story

As a contributor (human or agent),
I want a ready pnpm workspace with lint, tests, CI and the six package skeletons,
So that every later story starts from a green, bounded scaffold instead of inventing one.

## Acceptance Criteria

- AC-1: On a fresh clone (Node ≥ 20, pnpm 10), `pnpm install && pnpm lint &&
  pnpm test` all exit 0; `pnpm test` executes at least one (trivial) vitest
  suite in each of the six packages.
- AC-2: Workspace contains `@gitnebula/{contract,scanner,deps,githist,viz,cli}`,
  each with `"type": "module"`, an `exports` map (deep imports like
  `@gitnebula/contract/src/x` do not resolve), and only the AD-2 dependency
  edges declared in `package.json` (cli → all four Node packages + contract;
  scanner/deps/githist/viz → contract only).
- AC-3: ESLint 9 (flat config) + Prettier are root-configured; a file inside
  scanner/deps/githist calling `Date.now()` or `Math.random()` fails
  `pnpm lint` (AD-4); viz and cli are exempt from that specific ban.
- AC-4: `tsconfig` layout per AD-11: shared base, NodeNext resolution;
  `packages/viz` uses DOM lib and no `node:` types; the other five compile
  Node-side (`contract` additionally must not import `node:` modules —
  environment-neutral).
- AC-5: `.github/workflows/ci.yml` runs `pnpm lint` + `pnpm test` on push and
  PR, and is green on your branch.
- AC-6: MIT `LICENSE` (copyright holder: Łukasz Jundziłł) and `CONTRIBUTING.md`
  exist at the root; CONTRIBUTING covers: Conventional Commits with scope =
  module, the `Refs:`/`Agent:` trailers (also in PR bodies — squash merge),
  squash-merge policy, and how to run lint/tests.
- AC-7: `pnpm build` builds cli (tsup, may emit a placeholder binary) and viz
  (vite, may emit a placeholder page) — the two AD-11 build edges exist and
  run; internal packages have **no** build step.
