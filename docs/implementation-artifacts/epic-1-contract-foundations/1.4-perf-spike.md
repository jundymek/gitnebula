## Story

As the project's planners,
I want a measured answer on d3-force + Barnes–Hut + viewport-scoped unfold at 2,000 nodes,
So that Epic 2/3 viz stories freeze against a proven mechanism, not a hope.

## Context (binding)

- PRD FR-14/FR-16, §8 Q4; AD-5 (GraphEngine seam), AD-6 (Settled = max
  displacement < 0.5 px/frame × 30 frames), ADR-0006 (viewport-scoped
  unfold), addendum A4 (strategy: Barnes–Hut, freeze-on-settle, local wake).
- **This story is a gate**: its verdict decides whether Epic 2/3 viz specs
  launch as written or get amended toward the cosmos.gl path. Spike code may
  be throwaway; the measurement harness should be reusable (3.5 builds the
  CI version on it).
- `reference/mockup.html` shows the O(n²) loop you must NOT port — read it
  for aesthetics only.

## Acceptance Criteria

- AC-1: A spike page loads the synthetic 100-module/2,000-file fixture and
  runs d3-force with `forceManyBody` (Barnes–Hut) in three measured phases:
  (a) active simulation of all nodes, (b) frozen simulation + pan/zoom,
  (c) viewport-scoped unfold while panning at ≥ 1.8× zoom.
- AC-2: A scripted (not hand-driven) pan+zoom sequence measures fps per
  phase; methodology (frame counting, duration, hardware) is recorded.
- AC-3: A committed report `docs/dev/epic-1/1.4-perf-spike/README.md` states
  per-phase fps and ends with an explicit verdict line: `VERDICT: canvas-2d
  viable (>= 55 fps sustained in phases b and c)` or `VERDICT: escalate —
  cosmos.gl path` with the numbers that force it.
- AC-4: If the verdict is escalation, the report names exactly which Epic
  2/3 story specs need amending (2.5, 3.3, 3.5) and what changes — the
  cohort must not launch against a dead spec.
- AC-5: The local-settle question is answered empirically: unfolding a
  module wakes only its members (report shows global layout displacement
  during unfold stays under the Settled bound for non-member nodes).

### Debug Log References

- **Phase (c) unfolded nothing on the first run** (`unfoldEvents: 0`). The
  camera script panned around the origin using a hardcoded world radius, but
  the settled layout sat at x ∈ [−1173, 990], y ∈ [−1224, 1074]; the scripted
  path traversed empty space. Root cause found by dumping module bounds into
  the results JSON. Fixed by deriving the keyframes from the measured layout
  bounds; covered by a regression test in `camera-script.test.ts`.
- **Modules and files settled as two disconnected clusters.** Membership is
  `parent` in the contract, not an edge (ADR-0005), so the simulation graph had
  no module↔file connection at all: the module component drifted to (1034,
  −2010) while files stayed near the origin. Fixed by deriving member links for
  the layout, which is what "the Viewer derives member relations" implies for
  layout as well as rendering.
- **AC-5 failed at first with 129 px/frame of non-member displacement** — 258×
  over the Settled bound. Cause was in the spike, not in the mechanism: each
  unfold rebuilt one simulation over *all* active nodes and included
  `forceCenter`, which drags already-settled files on every wake. Fixed by
  per-wake simulations scoped to newly woken members with no centering force;
  re-measured at 0.0 px. Both findings are written up in the report because the
  Epic 3 unfold story needs them.
- **Test-quality check:** mutation-tested the harness before trusting it. The
  first version of `settle.test.ts` read `SETTLE_FRAMES` from the module under
  test, so setting it to 5 kept the suite green — self-referential and
  worthless. Rewritten to pin the AD-6 literals (0.5 px, 30 frames); the same
  mutation now fails 4 tests, and a `hypot`→`max` mutation and an fps-window
  mutation each fail one.

- **Codex review found two real defects, both fixed** (see Completion Notes).
  The first — rendered links derived from live wakes, so a module's import
  edges stopped being drawn once it settled — was a genuine under-measurement
  of render cost, not a cosmetic issue: peak rendered links went from an
  undercounted set to 5,546 and phase (c) mean frame work rose from ~1.14 ms to
  ~1.33 ms once fixed. The second was a report/evidence mismatch: the committed
  `results.json` came from a different run than the table quoted.

- **A second Codex round, after story 1.3 merged, found the biggest defect in
  the spike: phase (c) never collapsed a module on viewport exit.** Modules
  were added to the unfolded set and never removed, so the scripted pan
  accumulated 1,820 of 2,000 files — the exact opposite of ADR-0006's "off-
  screen modules stay collapsed", and therefore not the mechanism the story
  claims to measure. It escaped notice because it never hurt the numbers: the
  run held 59 fps either way, and `MANUAL_TESTING.md` even asserted the
  collapse behaviour in an eyeball step that no measurement backed. Fixed by
  diffing the wanted unfold set against the current one each frame
  (`unfoldTransition`) and by making wakes per-module instead of per-batch, so
  a collapse is a deletion rather than a re-seed of the survivors. Peak live
  file nodes fell from 1,820 to 260–300 and phase (c) mean frame work from
  ~1.3 ms to ~0.5 ms — the earlier evidence was conservative, not optimistic,
  which is why the verdict did not move.
- **The same round flagged that a settle timeout was indistinguishable from a
  settle.** Phase (a) capped at 3,000 frames and then continued as if Settled,
  so a non-converging layout would have produced a normal-looking result while
  phases (b) and (c) measured a layout frozen mid-motion. `SettleGate` now
  separates the two outcomes and `settleTimedOut` is recorded in the results.
- **Found while re-measuring: a background tab silently invalidates a run.**
  The first re-run took over 90 s in phase (a) against a normal 4 s, because
  Chrome throttles `requestAnimationFrame` on a hidden tab — and nothing in the
  output said so; the JSON, the phase structure and the status line were all
  well-formed. Added `VisibilityWatch`; `hiddenFrames` is recorded, and the
  page now labels the run `INVALID RUN` rather than `done`. This is the same
  defect class as the two above (an invalid run wearing the shape of a valid
  one), so all three are now summarised by a single `runValid` field that the
  report tells the reader to check first.
- **Fixture wiring, after 1.3 merged.** The loader fetched `./fixture.json`
  relative to the spike's Vite root, but the committed document lives in the
  contract package outside that root, so the fetch would have 404'd and dropped
  to the generator without saying anything useful. A dev-server plugin
  (`contractFixture`) now serves
  `packages/contract/fixtures/synthetic-100x2000.json` at that path, and
  `fixture.test.ts` asserts the real committed document parses into 100
  modules / 2,000 files with resolvable edge endpoints at both levels — so the
  wiring is covered without a browser.

### Completion Notes List

- Verdict: **`VERDICT: canvas-2d viable (>= 55 fps sustained in phases b and
  c)`** — 59 fps sustained in all three phases across three runs; phase (c)
  worst-frame work 3.6 ms against a 16.7 ms budget. AC-4 therefore does not apply: no Epic 2/3
  spec needs amending, stories 2.5/3.3/3.5 launch as written.
- The committed evidence is three runs against story 1.3's committed
  `synthetic-100x2000.json` (`fixtureSource: contract-fixture`, `runValid:
  true`), taken after the collapse fix. They replace the three
  `generated-fallback` runs recorded before 1.3 merged; the verdict is
  unchanged and the margins are wider.
- Since every phase sits at the vsync ceiling, fps alone could not show
  headroom, so per-frame work time (mean/p95/max) was added to the harness and
  is what the margin claims rest on.
- **Fixture provenance deviation, now resolved.** The first round of numbers
  was taken before story 1.3 merged, from an equivalent seeded generator
  (`generated-fallback`, 4,132 edges). 1.3 has since merged and the committed
  runs use the real document (1,095 edges). The generator survives only as a
  last-resort fallback, and a run that uses it is marked invalid.
- Three full runs are committed rather than one, after a Codex finding that the
  committed evidence and the quoted table came from different runs. An observed
  phase (a) outlier (45 worst-1s fps, one 107 ms frame) that did not reproduce
  is recorded in the report rather than dropped.
- Owner gate left unticked deliberately: the maintainer accepts the verdict at
  the M1 merge, not the implementing agent.
- Harness defect encountered and worked around, not fixed (per the supervised
  addendum): `~/.terminal-agents/scripts/agent-peek.sh` resolves peers under
  `~/dev/terminal-agents-agents/<peer>` while this cohort lives in
  `~/dev/gitnebula-agents/<peer>`, and `set-depends-on.sh` cannot derive
  `AGENT_ID` from `$PWD`, needing an explicit `AGENT_ID=arnold`.
- Spike tooling note: the dev server carries a small POST sink so a scripted
  run writes `results.json` instead of requiring numbers to be copied out of
  the console by hand. Dev-only (`apply: "serve"`), never shipped; the run
  output is gitignored and the recorded evidence is committed under `docs/dev/`.
