## Story

As a pipeline or viewer developer,
I want the frozen `analysis.json` JSON Schema with generated types and a validator,
So that every module builds against one machine-checked truth.

## Context (binding)

- PRD FR-6/FR-7 (contract content), ADR-0003 (churn fields), ADR-0005
  (contract shape: parent-only membership, two-level edges, bounded
  cochanges, stable sorts), AD-1 (intermediate types live here), AD-9
  (schema is source, types generated), AD-13 (`windowAnchor` in `Config`).
- The schema IS the project's central artifact (brief §7). Changing it later
  is a versioned act — get it right against the PRD Glossary, not against
  your intuition.

## Acceptance Criteria

- AC-1: JSON Schema (draft 2020-12) in `@gitnebula/contract` describes:
  `schemaVersion` ("1.0"), `repo` (name, remoteUrl nullable, analyzedAt,
  defaultBranch, `analysisWindowDays`, stats: files/loc/commits/languages),
  `nodes[]` (`id`, `kind` module|file, `parent` nullable, `path`, `layer`
  backend|frontend|infra|test|other, `loc`, `churn` 0..1, `commits` int,
  `authors`, `lastChangedAt`, `description: null`, `descriptionSource:
  null` — both nullable, required-present), `edges[]` (`source`, `target`,
  `kind: "import"`, `weight`), `cochanges[]` (`a`, `b`, `count`).
- AC-2: Type generation script produces committed TS types from the schema;
  a CI check fails when types are stale (AD-9); no hand-edited type drift is
  possible.
- AC-3: Package exports `validateAnalysis(data)` (ajv, compiled once) with
  error output usable in cli failure messages, and `SUPPORTED_SCHEMA_MAJOR`.
- AC-4: Intermediate pipeline types exported: `ScanResult`, `DepsResult`,
  `GitResult`, `Config` (including `windowAnchor: string` ISO, excludes,
  windowDays, layers overrides, hotspotThreshold, llm passthrough field).
- AC-5: Package remains environment-neutral: no `node:` imports anywhere in
  its runtime path (viz will import it in the browser); verified by the viz
  placeholder build still passing.
- AC-6: Unit tests: a valid minimal document passes; each required field's
  absence fails with a pointer to the field; an unknown `layer` value fails.

### Completion Notes List

- Schema is draft 2020-12, `additionalProperties: false` at every level, with
  `$defs` for the reused shapes (`layer`, `nodeKind`, `repo`, `repoStats`,
  `node`, `edge`, `cochange`). `$id` pins the version:
  `…/schema/analysis-1.0.json`.
- Types are generated by `scripts/generate-types.mjs`
  (`json-schema-to-typescript`) into `src/generated/analysis.ts`, committed,
  do-not-edit banner, ESLint-ignored, CI-verified fresh. The generator script
  is the only place in the package allowed `node:` imports.
- `validateAnalysis` compiles the schema once at module load (both the cli and
  the Viewer validate on a hot path) and returns a discriminated result that
  narrows to `AnalysisDocument` on success. Missing-property errors are
  rewritten to point at the absent field, not its parent, so the pointer is
  printable verbatim in an AD-7 cli message.
- `date-time` is registered as a local RFC 3339 validator rather than adding
  `ajv-formats`; it is the only format the contract uses. It validates
  component ranges and the calendar, not just digit placement — the first
  version was a shape-only regex, and the Codex review correctly caught that it
  accepted `2026-99-99T25:61:61Z`, which the Viewer would have rendered as NaN
  from an `Invalid Date`. Fixed with 24 added test cases (valid and invalid
  instants, leap day, leap second, offset bounds).
- Intermediate types in `src/pipeline.ts` derive from the generated contract
  types via `Pick`/`Omit`, so a schema change breaks the analyzers at compile
  time instead of drifting. Adds `AnalyzerWarning` for AD-7's counted
  non-fatal drops.
- Four shape decisions are carried in the PR body because later stories depend
  on them: `lastChangedAt` nullable, `description`/`descriptionSource` typed
  `null`-only, co-change `count` bound `>= 1` in the schema (`>= 3` stays
  analyzer policy per FR-7), and `repo.stats.languages` as a share map.
- Per-story docs follow the spec path (`docs/dev/epic-1/…`), not the generic
  pre-PR checklist's `docs/features/epic-1-omdb-data-layer/…`, which belongs to
  a different project. Divergence flagged.
- Not done, deliberately: no fixture `analysis.json` files (story 1.3), no
  widening of `description` to `string | null` (the describe-layer story's
  act), no CI trigger change (maintainer decision, revisited in story 4.2).
