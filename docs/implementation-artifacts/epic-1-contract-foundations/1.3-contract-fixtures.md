## Story

As an analyzer or viewer developer,
I want committed edge-case `analysis.json` fixtures and deterministic fixture git repos,
So that viz builds against the contract alone and githist tests have known history.

## Context (binding)

- PRD FR-6 (fixture list), AD-14 (fixture repos built, never committed),
  AD-13 (fixture tests pin `windowAnchor`), ADR-0006/PRD FR-14 (the
  synthetic 100-module/2,000-file fixture is the perf yardstick).
- These fixtures are the ONLY thing viz stories see until M2. Edge cases you
  skip here become integration surprises later — err toward nasty.

## Acceptance Criteria

- AC-1: `@gitnebula/contract` ships validating fixtures: empty graph, single
  module, cyclic imports (a→b→c→a at module level), module with zero files,
  zero-history repo (all `churn: 0`), and a synthetic 100-module/2,000-file
  document produced by a committed generator script (output committed too;
  regeneration is byte-identical — seeded).
- AC-2: A `fixtures/README.md` names each fixture's purpose and the edge it
  guards.
- AC-3: `test-fixtures/` contains build scripts that replay crafted commits
  with pinned `GIT_AUTHOR_DATE`/`GIT_COMMITTER_DATE` and fixed identity into
  gitignored `test-fixtures/.generated/`; running twice on any machine gives
  identical commit hashes (AC test does exactly that).
- AC-4: The crafted history covers: a rename (content preserved), a
  multi-file commit (co-change source), a file touched by 3 distinct
  authors, a file whose only commits predate the analysis window, and a
  Python + TS file mix.
- AC-5: The build scripts run automatically before tests (root pretest) and
  in CI; a fresh clone's `pnpm test` passes with no manual step.

### Debug Log References

- **Fixture-repo history parser under-counted authors.** The first
  `git log --name-status` parser split commits on blank lines, but
  `--name-status` itself emits a blank line between the commit header and the
  file list, so each commit was read as two records and the "3 distinct
  authors" assertion saw 1. Fixed by making the record separator explicit:
  `--format=%x00%H|%an|%aI` and splitting on NUL. The test found this by going
  red for the right reason before the parser was trusted.
- **`ValidationResult` is a discriminated union.** `fixtures.test.ts` initially
  read `result.errors` off the union for its failure message; that is a type
  error against the frozen 1.2 signature, since `errors` exists only on the
  `valid: false` branch. The test now narrows with `if (!result.valid)` and
  formats through the contract's own `formatValidationErrors`. Caught by
  `tsc --noEmit -p tsconfig.test.json`, not by a green test run.
- **Rebase onto 1.2 (PR #2).** Conflicts in `eslint.config.js`,
  `packages/contract/package.json` and `pnpm-lock.yaml`; `tsconfig.json`
  auto-merged. Resolutions: 1.2's eslint block supersedes mine (its
  `packages/*/scripts/**/*.mjs` glob already covers this story's generator),
  package.json unioned, lockfile regenerated rather than hand-merged. Nothing
  from either story was dropped.

### Completion Notes List

- **AC-1** — six fixtures ship in `packages/contract/fixtures/`: `empty-graph`,
  `single-module`, `cyclic-imports` (a→b→c→a at module level),
  `module-zero-files`, `zero-history` (all `churn: 0`) and the generated
  `synthetic-100x2000`. A directory-loop test validates every `.json` in the
  folder against `validateAnalysis`, so a fixture added later is covered with no
  test-code change. All six passed against 1.2's real schema on the first run
  after rebase.
- **AC-1 (seeded generator)** — `scripts/generate-synthetic-fixture.mjs` uses a
  mulberry32 PRNG with a fixed seed and reads neither the clock nor
  `Math.random`. A test regenerates the file in-place and asserts the output is
  byte-identical to the committed one.
- **AC-2** — `packages/contract/fixtures/README.md` carries a per-fixture table
  (purpose + the edge it guards) and the recipe for adding another.
- **AC-3** — `test-fixtures/build-fixture-repo.sh` replays crafted commits into
  gitignored `test-fixtures/.generated/history-repo` with
  `GIT_AUTHOR_DATE`/`GIT_COMMITTER_DATE` and both identities pinned per commit,
  gpg signing and template hooks disabled. The determinism test builds twice and
  asserts identical HEAD hashes.
- **AC-4** — one test per required history trait: a rename with content
  preserved (`R100 core/score.py core/scoring.py`), a multi-file commit, a file
  touched by three distinct authors (`web/api.ts`), a file whose only commits
  predate the pinned analysis window (`legacy/old.ts`, `windowAnchor =
  2026-01-01T00:00:00Z`, 365 days, AD-13), and a Python + TypeScript file mix.
- **AC-5** — the root `pretest` script runs the builder before `pnpm test`, so a
  fresh clone needs no manual step. CI needs no new step: `.github/workflows/ci.yml`
  already runs root `pnpm test`, which triggers the same `pretest`. That workflow
  is `workflow_dispatch`-only by the maintainer's standing decision (story 4.2
  revisits it), so there is no branch CI run to link.
- **Manual testing: not applicable.** The story ships test infrastructure only —
  fixture JSON, a generator script, a repo-builder script and automated tests.
  There is no UI, route or keyboard behaviour to exercise. Stated with the same
  reasoning in `plan.md`'s `## Manual testing` section.
- **Contract-shared files.** `packages/contract/tsconfig.json` gained an
  `exclude` of `src/**/*.test.ts` and a sibling `tsconfig.test.json` grants
  `types: ["node"]` to tests only, so the shipped runtime path keeps `types: []`
  and still fails to compile on an accidental `node:` import (1.2 AC-5 / AD-11).
  Coordinated with bob by peer message before either side landed; he adopted it
  as-is.

### Harness defect (not this story's to fix)

The pre-PR docs gate demands `docs/backend/epic-1/<task>/README.md`, but
`config/projects/gitnebula/project.env` declares `DOCS_TASK_DIR='docs/dev'` —
which is also what CLAUDE.md and this spec require. `spawn-agent.sh` writes the
default into each agent's `.env.agent` instead of the project value; alice,
arnold, superman and this agent all carry `docs/backend`. Reproduce with:

    grep DOCS_TASK_DIR ~/.terminal-agents/config/projects/gitnebula/project.env
    grep DOCS_TASK_DIR ~/.local/state/terminal-agents/pamela/.env.agent

Correcting the agent's own `.env.agent` is blocked by the harness hook as a
secret-bearing path, and superman ruled out both that route and any duplicate
README under `docs/backend/` (a path CLAUDE.md forbids). This story therefore
ships one README at the spec path and stops at the gate rather than routing
around it. The one-line fix belongs in `spawn-agent.sh` and is the maintainer's
call. Cost: PR creation for this story needs a human.
