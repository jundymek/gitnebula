## Story

As a maintainer restyling the chrome,
I want the tests pinned to hooks that survive a class rename, and the two
defects Epic 5 reported but never assigned finally closed,
So that the suite asserts behaviour rather than styling, and no later test
encodes a wrong number as the expected one.

## Context (binding)

- `epics.md` Epic 6; FR-28 (layer filter), UX-DR13 (filter controls carry
  `aria-pressed`, active set legible), NFR-11 (no contract change), AD-5.
- **Why the `data-testid` pass is narrow, and why it is justified at all.**
  There is not one `data-testid` in `packages/viz/src/`. That is not itself a
  problem: accessibility was a first-class AC throughout Epic 5, so every
  interactive **control** already carries a stable `id`, or a `role` +
  `aria-label`, or a `data-*` — `#layer-backend`..`#layer-other`,
  `#view-switch button[data-view="3d"]`, `#start-here`, `.sh-entry[data-id]`,
  `#p-isolate`, `#scope-bar`, a `role=combobox` search input. Those are fine
  and you leave them alone.
  The problem is the **readouts**. Existing jsdom tests are pinned to styling
  classes: `.p-row` carries **5** rules in `styles.css`, `.p-badge` **2**,
  `.sh-metric` **1**. A restyle breaks tests that are not about styling. This
  is pre-existing debt, not a cost of Epic 6 — you are stabilising tests that
  already exist.
- **The rule for where a `data-testid` goes.** Add one only where **both** are
  true: (a) the current hook is a CSS class, and (b) the value is unreachable
  from the `GraphEngine` interface, so a test has no choice but to read the
  DOM. Measured, that set is: the panel metric rows, `.sh-metric`, the legend
  rows, `.scope-bar-hidden`, `.scope-bar-back`, `.p-blast-row`. Nothing else.
- **What "unreachable from the engine" means, so you can check the rule
  yourself.** `GraphEngine` (`packages/viz/src/engine/types.ts:180-386`)
  exposes no edges accessor, no degree, no `repo` metadata and no `cochanges`;
  `getBlastRadius()` returns the currently *marked* set, not a node's partner
  list. So start-here's `metricLabel`, the blast-radius partner rows, and every
  label carrying `analysisWindowDays` exist only in the DOM. Conversely
  `getLayerFilter()`, `getScope()`, `getConnectedOnly()`, `getSelected()` and
  `getMode()` are engine-backed — regions whose value comes from those do not
  need a hook.
- **`header.ts` carries the literal instruction `**Do not rename.**` on two
  slot ids.** Honour it.
- **Debt 7a — the legend has no key for `other`.** `LEGEND_ENTRIES`
  (`packages/viz/src/chrome/legend.ts:27-33`) lists exactly the mockup's five
  entries: backend, frontend, infra, test, hot spot. `other` is missing, and
  `other` is the **largest** layer on this repository — measured in story 5.3:
  `other` 145, `backend` 111, `test` 97, `frontend` 7, `infra` 3, of 363
  nodes. So a reader gets an `other` toggle in the layer filter with no legend
  key. It was reported by 5.3 to 5.5, and 5.5 declined it for a good reason:
  `LAYER_COLOR.other` and `LAYER_COLOR.infra` are both `#7c8598`
  (`engine/constants.ts:16-24`), so adding a fifth entry produces **two
  identical swatches** and needs a palette decision rather than a line of code.
  The maintainer took that decision on 2026-09-05: **`other` gets its own
  fifth hue.**
- **Why 7a needs an ADR.** `reference/mockup.html` knows four layers — its
  `LAYER_COLOR` is `{backend, frontend, infra, test}` (line 515) and its
  legend names four. A fifth hue is a deliberate departure from the visual
  reference, which is exactly the class of decision `docs/adr/` exists for.
  Follow the house format: context → decision → consequences. ADR-0007 is the
  highest existing number.
- **Debt 7b — `hiddenCount().visible` ignores the layer filter.** The
  interface documents the field as the survivors of *every* filter including
  layers (`engine/types.ts:332-343`), but on the path where no scope and no
  connected-only filter is active the implementation short-circuits to
  `graph.nodes.length`. **Both engines behave identically.** It was found by
  5.7 while building the degradation sweep, which "read 2,100 for every sample"
  until the measurement was moved to the scene the renderer is actually handed;
  5.7 handed it to "5.3/5.4", both already merged, so nobody received it.
- **Why 7b is urgent now rather than someday.** Wave B's stories assert
  through this interface. A test written against today's behaviour would
  encode the wrong number as the expected one, and the defect would become
  load-bearing.
- **Watch the test fail first.** Epic 5 shipped a test that went green with the
  bug still present, because the fixture contained no node in the failing
  shape; reverting the fix and watching the test stay green is what caught it.
  For 7b, the failing shape is: a document with ≥ 2 layers, no scope, no
  connected-only, and a layer switched off. `root-files` has three layers
  (`backend` 2, `infra` 2, `test` 1) and is the natural fixture.
- **No contract change.** `analysis.schema.json` is untouched and
  `schemaVersion` stays `"1.0"` (NFR-11).

## Acceptance Criteria

- AC-1: `data-testid` is added **only** to the panel metric rows,
  `.sh-metric`, the legend rows, `.scope-bar-hidden`, `.scope-bar-back` and
  `.p-blast-row`. No control that already carries an `id`, a `role` +
  `aria-label` or a `data-*` gains one, and `header.ts`'s two "Do not rename"
  slot ids are byte-unchanged.
- AC-2: The existing jsdom tests for those regions are **moved onto** the new
  hooks rather than duplicated — the count of CSS-class selectors in
  `packages/viz/src/chrome/*.test.ts` goes down, and the story's README quotes
  the before/after count. A pass that only adds attributes has not paid for
  itself.
- AC-3: The legend gains an `other` entry with a fifth hue, distinguishable
  from `infra`'s grey, so every layer-filter toggle has a legend key; asserted
  by a test over `LEGEND_ENTRIES` that fails if two entries share a colour
  (FR-28, UX-DR13).
- AC-4: The fifth hue lands as an ADR in `docs/adr/` in the house format
  (context → decision → consequences), stating that it is a deliberate
  departure from `reference/mockup.html`'s four-layer palette and why the
  shared grey was no longer tenable once `other` gained a toggle.
- AC-5: `hiddenCount().visible` counts the survivors of the layer filter on
  the no-scope / no-connected-only path, **in both the 2D and the 3D engine**;
  pinned by a test in each, and each test watched red first against the
  unfixed implementation. The story's README states that this was done.
- AC-6: Any readout that displayed the wrong number is corrected with it, and
  the story names which readouts those were — or states, with evidence, that
  no readout consumed the wrong value.
- AC-7: `analysis.schema.json` is byte-unchanged, `schemaVersion` is `"1.0"`,
  `packages/viz/src/chrome/boundary.test.ts` passes unchanged, and no file
  under `packages/viz/ui/` is touched (that is 6.1's territory, and the two
  wave-A branches must not be able to conflict).
