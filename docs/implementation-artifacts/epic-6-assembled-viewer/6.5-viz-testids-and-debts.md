## Story

As a maintainer restyling the chrome,
I want the tests pinned to hooks that survive a class rename, and the two
defects Epic 5 reported but never assigned finally closed,
So that the suite asserts behaviour rather than styling, and no later test
encodes a wrong number as the expected one.

## Context (binding)

- `epics.md` Epic 6; FR-28 (layer filter), UX-DR13 (filter controls carry
  `aria-pressed`, active set legible), NFR-11 (no contract change), AD-5.
- **Why the `data-testid` pass is narrow, and why it is justified at all.**
  There is not one `data-testid` in `packages/viz/src/`. That is not itself a
  problem: accessibility was a first-class AC throughout Epic 5, so every
  interactive **control** already carries a stable `id`, or a `role` +
  `aria-label`, or a `data-*` — `#layer-backend`..`#layer-other`,
  `#view-switch button[data-view="3d"]`, `#start-here`, `.sh-entry[data-id]`,
  `#p-isolate`, `#scope-bar`, a `role=combobox` search input. Those are fine
  and you leave them alone.
  The problem is the **readouts**. Existing jsdom tests are pinned to styling
  classes: `.p-row` carries **5** rules in `styles.css`, `.p-badge` **2**,
  `.sh-metric` **1**. A restyle breaks tests that are not about styling. This
  is pre-existing debt, not a cost of Epic 6 — you are stabilising tests that
  already exist.
- **The rule for where a `data-testid` goes.** Add one only where **both** are
  true: (a) the current hook is a CSS class, and (b) the value is unreachable
  from the `GraphEngine` interface, so a test has no choice but to read the
  DOM. Measured, that set is: the panel metric rows, `.sh-metric`, the legend
  rows, `.scope-bar-hidden`, `.scope-bar-back`, `.p-blast-row`. Nothing else.
- **What "unreachable from the engine" means, so you can check the rule
  yourself.** `GraphEngine` (`packages/viz/src/engine/types.ts:180-386`)
  exposes no edges accessor, no degree, no `repo` metadata and no `cochanges`;
  `getBlastRadius()` returns the currently *marked* set, not a node's partner
  list. So start-here's `metricLabel`, the blast-radius partner rows, and every
  label carrying `analysisWindowDays` exist only in the DOM. Conversely
  `getLayerFilter()`, `getScope()`, `getConnectedOnly()`, `getSelected()` and
  `getMode()` are engine-backed — regions whose value comes from those do not
  need a hook.
- **`header.ts` carries the literal instruction `**Do not rename.**` on two
  slot ids.** Honour it.
- **Debt 7a — the legend has no key for `other`.** `LEGEND_ENTRIES`
  (`packages/viz/src/chrome/legend.ts:27-33`) lists exactly the mockup's five
  entries: backend, frontend, infra, test, hot spot. `other` is missing, and
  `other` is the **largest** layer on this repository — measured in story 5.3:
  `other` 145, `backend` 111, `test` 97, `frontend` 7, `infra` 3, of 363
  nodes. So a reader gets an `other` toggle in the layer filter with no legend
  key. It was reported by 5.3 to 5.5, and 5.5 declined it for a good reason:
  `LAYER_COLOR.other` and `LAYER_COLOR.infra` are both `#7c8598`
  (`engine/constants.ts:16-24`), so adding a fifth entry produces **two
  identical swatches** and needs a palette decision rather than a line of code.
  The maintainer took that decision on 2026-09-05: **`other` gets its own
  fifth hue.**
- **Why 7a needs an ADR.** `reference/mockup.html` knows four layers — its
  `LAYER_COLOR` is `{backend, frontend, infra, test}` (line 515) and its
  legend names four. A fifth hue is a deliberate departure from the visual
  reference, which is exactly the class of decision `docs/adr/` exists for.
  Follow the house format: context → decision → consequences. ADR-0007 is the
  highest existing number.
- **Debt 7b — `hiddenCount().visible` ignores the layer filter.** The
  interface documents the field as the survivors of *every* filter including
  layers (`engine/types.ts:332-343`), but on the path where no scope and no
  connected-only filter is active the implementation short-circuits to
  `graph.nodes.length`. **Both engines behave identically.** It was found by
  5.7 while building the degradation sweep, which "read 2,100 for every sample"
  until the measurement was moved to the scene the renderer is actually handed;
  5.7 handed it to "5.3/5.4", both already merged, so nobody received it.
- **Why 7b is urgent now rather than someday.** Wave B's stories assert
  through this interface. A test written against today's behaviour would
  encode the wrong number as the expected one, and the defect would become
  load-bearing.
- **Watch the test fail first.** Epic 5 shipped a test that went green with the
  bug still present, because the fixture contained no node in the failing
  shape; reverting the fix and watching the test stay green is what caught it.
  For 7b, the failing shape is: a document with ≥ 2 layers, no scope, no
  connected-only, and a layer switched off. `root-files` has three layers
  (`backend` 2, `infra` 2, `test` 1) and is the natural fixture.
- **No contract change.** `analysis.schema.json` is untouched and
  `schemaVersion` stays `"1.0"` (NFR-11).

## Acceptance Criteria

- AC-1: `data-testid` is added **only** to the panel metric rows,
  `.sh-metric`, the legend rows, `.scope-bar-hidden`, `.scope-bar-back` and
  `.p-blast-row`. No control that already carries an `id`, a `role` +
  `aria-label` or a `data-*` gains one, and `header.ts`'s two "Do not rename"
  slot ids are byte-unchanged.
- AC-2: The existing jsdom tests for those regions are **moved onto** the new
  hooks rather than duplicated — the count of CSS-class selectors in
  `packages/viz/src/chrome/*.test.ts` goes down, and the story's README quotes
  the before/after count. A pass that only adds attributes has not paid for
  itself.
- AC-3: The legend gains an `other` entry with a fifth hue, distinguishable
  from `infra`'s grey, so every layer-filter toggle has a legend key; asserted
  by a test over `LEGEND_ENTRIES` that fails if two entries share a colour
  (FR-28, UX-DR13).
- AC-4: The fifth hue lands as an ADR in `docs/adr/` in the house format
  (context → decision → consequences), stating that it is a deliberate
  departure from `reference/mockup.html`'s four-layer palette and why the
  shared grey was no longer tenable once `other` gained a toggle.
- AC-5: `hiddenCount().visible` counts the survivors of the layer filter on
  the no-scope / no-connected-only path, **in both the 2D and the 3D engine**;
  pinned by a test in each, and each test watched red first against the
  unfixed implementation. The story's README states that this was done.
- AC-6: Any readout that displayed the wrong number is corrected with it, and
  the story names which readouts those were — or states, with evidence, that
  no readout consumed the wrong value.
- AC-7: `analysis.schema.json` is byte-unchanged, `schemaVersion` is `"1.0"`,
  `packages/viz/src/chrome/boundary.test.ts` passes unchanged, and no file
  under `packages/viz/ui/` is touched (that is 6.1's territory, and the two
  wave-A branches must not be able to conflict).

### Debug Log References

**Red-first evidence.** Every assertion this story relies on was watched fail
against the unfixed code before the fix landed:

| test | file | observed red |
| --- | --- | --- |
| 2D survivor count | `engine/filter.test.ts` | `expected 6 to be 3` |
| 2D `scope` event on leaving a scope | `engine/filter.test.ts` | `expected 6 to be 3` |
| 3D survivor count | `engine/engine3d.test.ts` | `expected 6 to be 3` |
| 3D agrees with 2D | `engine/engine3d.test.ts` | `expected 6 to be 3` |
| legend: no two entries share a colour | `chrome/legend.test.ts` | `expected [ '#7c8598: infra + other' ] to deeply equal []` |
| legend: `other` differs from `infra` | `chrome/legend.test.ts` | `expected '#7c8598' not to be '#7c8598'` |

The last two were produced by temporarily reverting `LAYER_COLOR.other` to the
old grey and re-running, then restoring it.

**A test that revealed a wrong assumption.** The first draft of the 2D `scope`
event test toggled a layer with no scope active and expected an event. It got
`undefined`: `onLayerFilterChanged` returns early when
`scopeId === null && !connectedOnly`, so no `scope` event fires at all on that
path. That guard is deliberate and was left alone; the test was rewritten onto
the genuinely reachable path — *leaving* a scope while a layer filter is on,
which reaches `emitScope` with nothing left to consult. Worth recording because
the first version would have "passed" only by forcing an unnecessary behaviour
change into the engine.

**A cross-engine failure that was the point.** After the 2D fix and before the
3D one, the new "3D agrees with the 2D engine" test failed *because the two
engines disagreed*. That is exactly the drift ADR-0007 predicts for a
`GraphEngine` member implemented twice, and it is now regression-tested.

**Harness defect, not fixed here, reported.** Nine tool calls were blocked with
`cohort intent-sync incomplete` after intent-sync was genuinely complete. Cause,
confirmed in the installed hook and independently by `superman`:
`hooks/pre-tool-use.sh:2829` tests `"$CWD/intent.synced"`, where `CWD` is the
working directory of the tool call rather than the worktree root — so any
command issued after a `cd packages/viz` cannot see the marker. It is a
terminal-agents bug, not a gitnebula one; per the supervised-cohort rule it was
worked around (run everything from the worktree root and scope with
`pnpm --filter`) rather than patched, and `superman` has reported it to the
maintainer. Nothing about it is in this branch.

**One repo-config gap, deliberately not fixed.** `.prettierignore` lists
`plan.md`, `DECISIONS.md` and `PR_SUMMARY.md` as worktree scratch files but not
`intent.md`, which is a newer harness artifact, so `pnpm lint` fails on any
cohorted agent's worktree. `intent.md` is git-ignored and never reaches a
commit, so the local fix was to format it. The one-line `.prettierignore`
addition was left alone on purpose: it is shared config that story 6.1's agent
hits identically, and two branches patching it is worse than the gap. Flagged
for the maintainer.

### Completion Notes List

- **All seven ACs met.** AC-2's before/after is **106 → 75** class-selector
  literals in `packages/viz/src/chrome/*.test.ts` (−31, −29%), reproducible
  from git with the command quoted in the story README.
- **The six hooks are declared in one new file**, `chrome/testids.ts`, rather
  than scattered as string literals. This is a small addition beyond the letter
  of the spec, taken because AC-1's constraint is "only these six" and a single
  file makes that checkable; it also carries the two-part rule for adding a
  seventh. No control that already had an `id`, a `role` + `aria-label` or a
  `data-*` gained one; `header.ts` has zero diff.
- **`LAYER_COLOR.other` is `#cf81cf`.** The decision to give `other` a fifth
  hue was the maintainer's (2026-09-05); only the value was chosen here, by
  measured CIE L\*a\*b\* separation against every colour already on the canvas.
  ADR-0008 carries the method, the table and four rejected alternatives.
- **`--cochange #ff5fa2` constrained the choice and is easy to miss**, because
  it is not part of UX-DR1. The obvious "nebula pink" was rejected for
  colliding with the co-change ring; cyan was rejected because its nearest
  neighbour is `infra`, the colour the change exists to separate `other` from.
- **UX-DR1 is not contradicted.** Its inventory is the mockup's four layers
  plus `--hot` and the void; `other` was never in it, and
  `LAYER_COLOR.infra` is unchanged at `#7c8598`.
- **AC-6's answer is "no readout consumed the wrong value", with evidence.**
  The only consumer is `scopeIsEmpty`, guarded by `scopeId !== null`, while the
  defect fired only when `scopeId === null`. The layer filter's own readout is
  fed by the separate `filter` event and was always correct. Three tests in
  `chrome/scope-bar-wiring.test.ts` pin this rather than leaving it as prose.
- **One deliberate extension of scope, inside the story's two engine
  allowances:** `emitScope()` in both engines carried its own copy of the
  defective expression one line below a call to `hiddenCount()`. Fixing only
  the accessor would have left the wrong number on the path chrome actually
  subscribes to, so both now read `counts.visible`. Recorded as D4 in
  `DECISIONS.md`.
- **One deliberate narrowing, flagged rather than hidden:** `types.ts`
  documents `visible` as the survivors of scope, connected-only, layers **and**
  semantic zoom. Only the layer half — debt 7b as reported, and the half wave B
  asserts through — is corrected. Answering the semantic-zoom half on the
  null path would mean reaching into `memberLayouts` and the scene builder,
  which is renderer work the story's territory excludes. The docstring's
  semantic-zoom clause was left untouched. Recorded as D5.
- **`styles.css` gains no `--other`** and is not touched: only `--backend` of
  the five layer variables is actually consumed, the legend swatch reads
  `LAYER_COLOR` at render time, and the file is outside this story's declared
  territory. Reasoned in ADR-0008.
- **`MANUAL_TESTING.md` was executed, not merely written**: 22 of 26 steps ran,
  including a full pipeline run on this repository (433 nodes; `other` measured
  at **42.5%** and `infra` at **0.7%**, re-confirming debt 7a's premise on this
  branch) and a served-bundle check showing all six hooks and the new hue reach
  the shipped HTML. The 4 unchecked steps are browser look-and-feel and
  screen-reader checks: the Claude browser extension is not connected in this
  environment, so no headless path could observe a rendered colour. Two of them
  are the only judgement in this story a measurement cannot settle — whether
  42.5% of the map in orchid still reads as a nebula — and they are the
  reviewer's to close.
- **No `PERFORMANCE.md`**: the story touches no stated performance property,
  and project rules say not to invent budgets to test against. The gzipped
  bundle is unchanged at 72.90 kB against ADR-0004's 2 MB budget.
- **Cohort:** synced with `alice` (6.1) before any edit. She confirmed 6.1 is
  additive and touches nothing under `packages/viz/src/`; the two branches share
